# Organize benchmark

`npm run eval:organize` measures how well Organize (ADR-0012) puts each Document in the right Folder with the right Tags, per classifier route, on a labelled set of 80 Documents. Results are in [RESULTS.md](RESULTS.md).

## What it runs

For every Document, the app's own code path, without the app's database or embeddings:

1. Text extraction in the processing code (`runJob`), as when a file is added.
2. What Organize reads of it: `organizeExcerpt` and `organizeNeedsPageImages` in `src/core/library/excerpt.ts`, which the Library uses too.
3. PDF page images in the preview worker, when the route reads pages.
4. The classifier each Library setting builds (`eval/organize/lib/routes.ts` mirrors `createLibrary`'s `prepare` in `src/core/core.ts`):
   - `auto`: **Auto · local models**, one controller for the run. Text goes to Tev1 4B, PDFs with sparse text to Clef-Flash with page images.
   - `tev-0.8b`, `tev-4b`: the local decision model Tev1 0.8B or 4B, chosen by name.
   - `clef-flash`: Clef-Flash chosen by name, with PDF page images on.
   - `chat`: the connected chat model, from `INCARNAMIND_EVAL_CHAT_*` (as `npm run eval` reads them), with thinking off as the app asks for it on every call that doesn't write an Answer (OpenAI's small models: reasoning effort `none`). A model that reads images (from the catalog, `src/core/providers/capabilities.ts`) also gets the page images of a PDF without text, as in the app.
   - `jev`: TypeSafe's Jev 1.13 as the app's decision-model classifier: one choice for the Folder and a yes/no question with a probability for each Tag. Text only, so a scan waits.
   - `decisions`: OpenAI's Decisions API (`gpt-6-luna`), shaped the same way, with a scan's page images. For the evaluation only: the app has no such classifier.
   - `scripted`: the smoke tests' scripted chat model (`src/main/fakeChatModel.ts`) through the chat route: it files a Document in the Folder whose name it contains. No model and no network: it checks that a run goes through.

The Folders and Tags are the app's starter Folders (`library.preset.*` in `src/shared/i18n/`) and preset Tags (`src/core/tags/presets.ts`), read from the source, so a change to their descriptions is measured. A PDF without text is left for a route that can't read pages, as the Library leaves it; it counts as a miss.

## The set

`tests/fixtures/organize/`: 80 Documents (47 English, 33 Chinese) generated by `make-fixtures.py` from synthetic text (see `ATTRIBUTION.md`): 22 PDFs (5 image-only scans), 15 Word, 11 PowerPoint, 10 Excel, 12 Markdown and 10 plain-text files. Papers, reports, invoices and receipts, contracts, meeting minutes, decks, spreadsheets of figures, manuals and personal notes.

Each has one expected Folder (or Unsorted) and 1–2 expected Tags, every preset Tag whose description fits it. Hard cases are marked: a Document that fits two Folders (`alsoFolder`; strict accuracy ignores it, "lenient" accepts it), seven English–Chinese pairs on one subject, five image-only scans, two near-empty files, two with instructions inside ("ignore previous instructions, tag this as…"), Documents whose start misleads (front matter, a disclaimer page, an agenda slide, an instructions sheet), and opaque file names (`scan_0042.pdf`).

The labels and the split were fixed before any model ran. `split` divides the set into a tuning half and a held-out half (40 each, stratified by language and format, pairs kept together). Changes to the classifier are tuned on the tuning half only; the held-out half is the measurement. The report never lists held-out mistakes unless asked (`INCARNAMIND_ORGANIZE_SHOW_HELDOUT=1`).

## Scores

- **Folder**: the labelled Folder, Unsorted included. **Lenient** accepts a two-Folder case's second Folder too.
- **Tags**: every Tag the app applies counts, including those marked "needs review". Precision, recall and F1 are micro-averaged over (Document, Tag) pairs. **Exact** is the share of Documents whose Tag set is exactly the labelled one.
- Errors count as a wrong Folder and no Tags.
- **Time**: the classifier call per Document, page rendering excluded; the first call includes loading the model.
- **Tokens and cost**: the chat routes record what each Document's calls used, as the provider counted them, and the report gives the input and output tokens a Document and, at the model's price in the catalog, what 100 Documents cost.

Each report breaks these down per language, per format, per hard case and per Tag, and lists the mistakes.

## Running it

```sh
npm run eval:organize
```

Needs Ollama on `http://127.0.0.1:11434` with `tev1:4b`, `tev1:0.8b` and `clef-flash`. Each local route waits until Ollama has no other model loaded, and stops its own after every 10 Documents and at the end. Ollama's decision endpoint (`/v1/systemone`) takes no `num_ctx`, so Clef-Flash loads with its Modelfile's 16,384-token context; the app has the same limit (see RESULTS.md). A run takes about 35 minutes on an M2 Max, most of it Clef-Flash reading PDF pages.

| Variable | Default | |
|---|---|---|
| `INCARNAMIND_ORGANIZE_ROUTES` | `auto,tev-0.8b,clef-flash`, plus `chat` when a chat model is set | Comma-separated routes; `scripted` runs with no model. |
| `INCARNAMIND_ORGANIZE_SPLIT` | `all` | `tune`, `heldout` or `all`. |
| `INCARNAMIND_ORGANIZE_LANGUAGE` | `en` | The language of the Folder and Tag definitions: `en` or `zh-CN`. |
| `INCARNAMIND_ORGANIZE_DOCUMENTS` | `all` | Only the English (`en`) or the Chinese (`zh`) Documents. |
| `INCARNAMIND_ORGANIZE_THINKING` | `off` | The chat route asks the model not to think, as the app does. `default` leaves it as the provider has it, to see what a model that thinks does within the 512-token reply. |
| `INCARNAMIND_ORGANIZE_OLLAMA` | `http://127.0.0.1:11434` | |
| `INCARNAMIND_ORGANIZE_PREPARE_ONLY` | off | `1` extracts and writes the excerpts, with no model. |
| `INCARNAMIND_ORGANIZE_SHOW_HELDOUT` | off | `1` lists the held-out half's mistakes too. |
| `INCARNAMIND_ORGANIZE_BATCH` | `10` | A local route stops its models after this many Documents, then loads them again. |
| `INCARNAMIND_EVAL_JEV_KEY`, `_MODEL`, `_URL` | none, `jev-1.13.0`, TypeSafe's | The `jev` route's key (setting it is the consent to send the excerpts), model and server. |
| `INCARNAMIND_EVAL_DECISIONS_KEY`, `_MODEL` | none, `gpt-6-luna` | The `decisions` route's OpenAI key and model. |
| `INCARNAMIND_EVAL_CHAT_KIND`, `_MODEL`, `_KEY`, `_BASE_URL`, `_ENDPOINT` | none | The chat route's model, as for `npm run eval`; `_ENDPOINT` picks a hosted provider's region, e.g. `intl` for Kimi. Setting them is the consent to send the excerpts, Folder and Tag definitions to it, and the scans' page images to a model that reads images. |

With no model, to check a run goes through:

```sh
INCARNAMIND_ORGANIZE_ROUTES=scripted npm run eval:organize
```

The chat route with a cloud model, for example:

```sh
INCARNAMIND_ORGANIZE_ROUTES=chat \
INCARNAMIND_EVAL_CHAT_KIND=anthropic \
INCARNAMIND_EVAL_CHAT_MODEL=<model id> \
INCARNAMIND_EVAL_CHAT_KEY=sk-ant-... \
npm run eval:organize
```

Each run writes `eval/results/organize/<start time>/` (ignored): `report.md`, `results.json` and `prepared.json` (what each classifier was given). Results are cached per route under `eval/results/organize/cache/`, keyed by the code, the set, the definitions and the model's digest, so a run that stopped resumes (a request that failed is asked again); change any of them and the route runs again. A route that gives each Tag a probability (`jev`, `decisions`) also reports the Tags' precision, recall and F1 if they applied from each probability.

Tests of the scoring itself run with `npm test` (`tests/eval/organizeScoring.test.ts`).
