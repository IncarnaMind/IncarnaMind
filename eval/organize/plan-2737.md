## A run that counts

- **A run counts only if no model request in it failed, was rate-limited or timed out**, read from the run's own request record. Commit d979e55c4 saves that record into each run's `results.json` before the run's data folder is removed:
  - every request the app's meter made, a refused one included (the meter marks a request refused before any reply as deleted);
  - a line `Requests: N answered, R refused, U ended without a reply`.

  A run with any refused request, any that ended without a reply, or that ends in an error is **void for a technical reason**: kept in the record, struck, and run again.
- **A void for the shared rate limit is "not run yet."** It doesn't use up the one technical rerun, and there is no cap on these. The next try waits until the limit eases, at least a minute. Three in a row stop the stage, and that is reported.
- **Every other technical failure** has the one rerun, as above.
- **The judge's topic questions** go to the model outside the app's meter, and decide nothing here. A judge request that fails after its retries ends the run, which is then a technical failure.

## The rule

1. **Five runs an arm, each language, at every stage:** the isolation stage and the final gate.
2. **The tolerance** is `main`'s standard error: the sample standard deviation of `main`'s five runs (n − 1), over the square root of five, with a floor of one percentage point. It is worked out separately for each measure, each language and each stage, from `main`'s runs of that measure there.
3. **No worse.**
   - Different-label pairs: the arm's mean is no higher than `main`'s mean plus the tolerance.
   - Filed: the arm's mean is no lower than `main`'s mean minus the tolerance.

   Both are read with the second Folder honoured; the labels as written are reported beside them.
4. **The 10% bar on the 40 in Chinese** belongs to the final gate, since the isolation stage has no 40. It holds on every run of the final gate, with no tolerance.
5. **One extension, at most once a comparison, for point 3 only.**
   - An arm is in the extension zone when it misses point 3 by more than one tolerance and no more than two from `main`'s mean, the tolerance being point 2's, floor included:
     - different-label pairs: its mean is above `main`'s mean plus one tolerance, and no higher than `main`'s mean plus two tolerances;
     - Filed: its mean is below `main`'s mean minus one tolerance, and no lower than `main`'s mean minus two tolerances.
   - In the zone, five more runs are made for that arm and for `main`. It is judged on all ten by the same rule, the tolerance recomputed from `main`'s ten.
   - Missing by more than two tolerances, it fails.
   - There is no extension for point 6, and none at the final gate for point 6: showing a gain on a second draw after missing on the first is choosing the draw.
6. **Filing more.** A second-look arm (part 2, part 2b, and both arms) qualifies only if both of these hold; level with `main`, it is dropped, not merged:
   - its Filed mean is above `main`'s mean plus the tolerance in at least one language;
   - in the other language it is not below `main`'s mean minus the tolerance.
7. **Part 3** qualifies when it is level under points 3 and 4: the examples taken from the tuning set shouldn't stay, so level is enough for it.
8. **The both arms** are judged as second-look arms, so point 6 applies to them. "Both, 2b" is judged only if part 2b qualifies alone.

## Choosing

- **More than one qualifies:** the arm with the highest Filed is chosen, as the mean of its English and Chinese means. A tie goes to the lower different-label mean, measured the same way. A tie there goes to the arm with fewer parts.
- **No second-look arm qualifies:** part 3 alone goes forward if it qualifies.
- **Nothing qualifies:** nothing goes forward. #2917 drops both parts, and the result is reported as it is.
- **The report gives every run's numbers,** and beside each mean `main`'s lowest and highest run and the tolerance.

## The final gate, once

The arm chosen runs beside `main` at the commits above, five runs each, in turns, on:
- the fresh set: English Documents with the interface in English, Chinese with it in Chinese;
- the old held-out 40: all 40 Documents with the interface in English, then in Chinese;
- the 500 set (seed 1), with the interface in English, then in Chinese.

Only the aggregate lines are read. Each set and language is judged on its own. The arm merges only when all of these hold:
- **every set:** point 3, with point 5's extension available once;
- **the 40 in Chinese:** point 4;
- **the fresh set and the 40, if the arm is a second-look arm:** point 6 again, set by set, with no extension;
- **the 500:** point 3 only.

If it fails, it doesn't merge, and that is reported. This round changes nothing in the choice.
