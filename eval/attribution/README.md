# Source, speaker, context and time checks

The check can find a quote without retaining a separate result for the source, speaker or period its sentence asserts (#2003). These fixtures exercise those attributes under the same Check and its ordinary part rows.

`cases.json` contains 40 synthetic sentences: 20 English and 20 Simplified Chinese, with 48 Sources and 40 isolated scope profiles. The golds are 12 Supported, 16 Unsupported and 12 Contradicted. The ten explicitly reversed-context cases form the 9-of-10 contradiction bar. Correct attribution, preserved qualifications, historical periods and a fresh present-time statement guard against rejecting every case.

| Case family | Cases | Required behavior |
| --- | ---: | --- |
| Named source | 8 | Correct report; wrong report; missing name; duplicate names requiring a choice |
| Speaker | 6 | Correct named speaker; another named speaker; anonymous label |
| Context | 12 | Five reversed-context pairs and one preserved-qualification pair |
| Time | 14 | Historical period; newer conflict; old-only scope; file-date decoy; expired period; no period; fresh current statement |

The injected Check clock is `2026-10-29T12:00:00.000Z`. Present-time claims use the Source's stated period and the 12-month rule, never the file timestamps. Duplicate names and old-only present-time cases have Unsupported golds. An outside-scope newer notice stays unavailable to the model.

Each case retains its complete original assertion. The 28 required facet targets are literal UTF-16 ranges for the case's source, speaker or time focus; they are judged in that assertion's context. Native figure anchors identify occurrences, not values or invented figure ids. Neither is a second overlapping sentence row. Secondary attributes are not assigned a verdict merely by copying the parent gold.

Golds, rationale, proof references, fixture ids and expected targets are scorer data. They must never be included in a model request. Only the assertion, language, ordinary check context and the chosen profile's in-scope Source material are inputs. Import Sources through the normal core; map fixture ids to the actual random Document ids rather than presenting fixture ids as evidence.

The intended measurement uses Claude Haiku 5.5 and Claude Sonnet 5.5 before and after the change, preserving every miss and recording all requests and latency. Kimi has not run because it has no balance. The baseline must include the landed parts implementation. A plain fact's normal search/cite/verdict path retains three requests. Facet judgments share the existing Run; strict confirmations, bounded recovery and additional scoped searches are counted as actual requests. Scripted cases test missing/malformed facet results, persistence, Undo and request accounting; they do not measure model quality.

Real-model runs are pending funding. The default adapter is zero cost; the separate paid entry requires explicit funding inputs; full execution additionally requires both candidate pilot reports to pass its promotion gate. Scripted integration checks do not establish real-model quality.

`scoring.ts` builds an allowlisted Check input with imported Document UUIDs, and retains every returned result or missing result in the frozen denominators. A native-verdict hit is reported separately from scope, expected-Source and physical-quote checks. Decisive newer/context coverage is a separate conservative diagnostic; finding a short literal quote does not prove a context reversal. None of these helpers replaces semantic review or enables a model runner. The scripted tests cover input leakage, false evidence, missing results and blanket rejection at zero cost.

## Zero-cost adapter

Run the existing evaluation host against the dry entry point:

```sh
npx vitest run --config eval/vitest.config.ts eval/attribution/run.attribution.eval.ts
```

This command uses a scripted model with no external requests. It imports all 48 exact Source texts, calls public `checkClaim` for all 40 assertions with their actual imported UUID scope, and injects the frozen Check clock. Automatic tagging is disabled before import. It sends no gold, rationale, proof references or expected facet/figure targets to the model. The deliberately uninformative mock response tests loading and retention; its scores are not model-quality results.

Reports go to a new `test-results/attribution-eval` directory. Each completed case and its request traces are appended to `outcomes.jsonl`; `report.json` retains all 40 rows, every miss and actual returned parts, plus the full measured source head, source-diff hash and fixture hash. The fixture SHA-256 is `a62d633b30fdd0413498378f83472b526db0bd6c2092a82f6953cf112c64e4ce`.

`INCARNAMIND_ATTRIBUTION_ARM=before` labels a dry baseline; `after` is the default. Use the identical frozen fixture and adapter at the landed baseline and candidate heads. The manifest identifies the actual source; a dirty dry run cannot be presented as a clean measured candidate. This adapter is standalone Core measurement, not a Note/Verify or UI pipeline. It reports every observed sort request without inventing an amortized Note/Verify sort count. Sampling seed, temperature and output limits are recorded as actually sent; absent values stay null.

The observer wraps both SDK entry points, including unmatched setup requests, strict contradiction confirmations, errors, unfinished streams and cancellations. It retains raw synthetic Tool inputs/results, text replies, latency, input/output and separate cache-read/cache-write usage. Missing or invalid counts stay unknown; missing cache details are never zero-filled. Error records keep only an allowlisted error class and numeric status, without headers, credentials, options or whole Error objects. Per-language summaries show all 20 cases, requests per check, strict requests, total/mean/p50/p95 latency and native false Supported/Contradicted counts. Exact target-row presence is diagnostic; a parent verdict never supplies a missing facet verdict. Native and strict physical-evidence scores remain separate.

Frozen modification timestamps are applied before import. Portable file creation time cannot be assigned through the ordinary importer: reports retain the declared creation timestamp, actual file timestamps and imported Document metadata with `createdAtApplied: false`. Source bytes are never modified to fake metadata.

The dry entry refuses every mode except `dry` before opening a host and never calls a credential/config loader. The separately funded entry requires explicit opt-in, exact model/source/data pins, one cumulative approved budget across both heads, conservative reservation before every generate/stream call, actual cache-write settlement and unreleased maximum holds for unknown usage. It must stop the arm on auth, out-of-credit or budget errors, preserve unstarted rows, and never retry a case for quality or switch providers. The app's monthly meter alone does not supply this experiment-wide guarantee. No paid cost forecast is inferred from the mock's token counts; those requirements remain a funding gate.


## Guarded pilot preparation

`run.pilot.attribution.eval.ts` is a separate, default-disabled pilot entry. It accepts only the ordered cases `N01-en`, `C03-zh-CN`, `T02-en` and the two specified Anthropic models. The pilot phase still refuses any list beyond those three cases; the separately authorized full phase is described below. It requires an explicit cumulative dollar ceiling, both clean full source pins, the frozen fixture hash, a hashed model-specific USD rate snapshot and one shared pilot ledger. These prerequisites are checked before runtime credential access. There is no default budget and no provider fallback. The cumulative pilot ceiling cannot exceed the authorized $2.00 across both heads and models.

The pilot uses the same import, injected clock and public `checkClaim` driver as the dry adapter. It preserves the app's output policy: each already-defined limit is kept. Only an undefined limit becomes explicit at the pinned models' proven app/SDK default of 128,000 tokens; an unproved default is refused. This is not the forced last-step limit of 8,000, which applies only when the app itself chooses that step. Sort, confirmation, evidence and other helper limits remain as supplied. No new output clamp, prompt envelope or attempt limit is added. The observer records the explicit sent limit, and each reservation uses that same limit plus conservative prompt/cache cost. An insufficient ceiling refuses before the provider is called. Unknown cache billing, missing usage, aborts and interrupted requests keep their full reservation; reopening a ledger never clears this exposure. Billing/auth errors stop the arm without retrying another credential.

Each requested case remains in the report, including errors and unstarted cases. The request journal includes generate/stream attempts, abandoned first turns, sorting, guards and unmatched setup work. Error status stays failed if a later finish arrives. Reports separate usage-priced cost, unresolved maximum exposure and an unknown invoice amount. Full execution has a separate promotion and cumulative ceiling; no paid command is included here.

The admission token bound is the UTF-8 byte length of the serialized prompt, function tools and response format, plus 1,024 tokens of fixed provider framing, 128 per message and 256 per function tool. This deliberately reserves bytes rather than the app's average-token estimate. Requests with unserializable data, media, provider-executed tools or separately billed inference options are refused. The rate snapshot must cover every applicable billing tier and explicitly identify the existing five-minute cache policy; other cache billing stays unpriced and stops admission. These are accounting checks, not changes to the request's output or sampling policy.

The single custom history kind `anthropic.message_start` is admitted as stream metadata: the installed SDK omits it from outbound request bytes. A local endpoint capture and an SDK regression test compare the stream bodies with and without that item. Other custom kinds remain unpriced and refused; metadata never supplies billing usage.

The pilot also requires the declared shared adapter, scorer, helper and entry hashes to match before runtime credential lookup. Its ledger binds both source pins, the fixture, ordered case IDs and shared host hashes. Billing/auth stop reasons persist even if the provider reports zero usage. A fresh process refuses an already attempted arm/model/head; it can run a distinct arm/model under the same unchanged cumulative ceiling. There is no quality-rerun or reset option.

## Full-phase promotion

The same default-disabled entry accepts `INCARNAMIND_ATTRIBUTION_PHASE=full` only with the exact ordered 40 IDs in `cases.json`, the same two models, clean before/after source pins, frozen fixture and shared adapter/scorer/host/entry hashes. Its explicit cumulative ceiling cannot exceed **$3.75 across both heads and models**. The pilot remains capped at **$2.00** and retains its three-case list; neither phase has a default funded ceiling.

Before runtime credential lookup or provider construction, full execution requires `INCARNAMIND_ATTRIBUTION_PILOT_RECEIPTS`: a JSON list of two `{ "path": ".../report.json", "sha256": "..." }` references, one for each candidate model. These must be complete after/pilot reports from the exact same candidate source, fixture and shared host hashes. Partial finally receipts are insufficient. All three rows must have returned without failure or a stopped/unknown/open billing hold. The existing scorer is run again over the actual imported Document UUID map: native golds, scoped expected Sources and physically found quotes must pass. Every required literal facet span/kind must appear exactly once with a terminal verdict and actual found, scoped quote evidence. Parent verdicts do not fill absent facet rows. The pilot focus specifically requires N01's Source facet to be Supported and T02's time facet to be Contradicted; an ordinary contradiction cannot conceal an Unsupported time result. This does not assign other facets their parent's gold. Settled requests also need finite nonnegative input/output/cache counts, with cache partitions no greater than total input; billing flags alone are insufficient. Baseline quality misses do not decide promotion. Report hashes are retained in the full manifest and ledger; no gold or promotion data is sent to a model.

Before each new full-phase request, the same locked ledger update sums only settled charges. If settled spend exceeds **$2.80**, it persists a stop and refuses the request before reservation or provider entry; exactly $2.80 may admit a request whose maximum still fits $3.75. Reserved and unknown holds remain charged exposure and never count as settled or get released. A final request that settles beyond $2.80 can still complete; the stop gates only a subsequent request. Partial results remain retained.

Use a separate, explicitly authorized full-phase ledger. Its phase, ordered case list, source/fixture/shared hashes, report hashes and ceiling are immutable. Existing phase-less pilot ledgers remain readable as pilot and cannot become full ledgers. Unknown usage retains maximum exposure, admission/billing/auth stops remain durable, and an attempted arm/model/head cannot be quality-rerun. A refused or unresolved pilot cannot provide the successful reports needed for promotion. All output limits, sampling, usage accounting and the provider/model refusal policy remain unchanged.

## Explicit seven-cell recovery

The separately authorized recovery phase is after-only and admits exactly these ordered cells: Haiku — N03-en, S01-en, S01-zh-CN, T07-en, T07-zh-CN; Sonnet — S02-en, S02-zh-CN. It never reruns Sonnet's five context misses or a successful cell. The original 40-case reports and pilot receipts remain immutable, with their original source/host pins. Recovery results retain the fixed clean source head and current host hashes separately; they are not a replacement 40-case run and do not erase earlier misses. Recovery outcome quality never triggers a retry or filters a measured row.

Before any runtime credential lookup, recovery requires both hashed complete original after 40 reports, their known settled usage, matching original pins and actual native failures for the approved cells rechecked by the existing scorer. The original successful pilot receipt hashes are still required against those original pins. INCARNAMIND_ATTRIBUTION_RECOVERY supplies { "lineageSHA256": "…", "originalAfterReports": [{ "path": "…", "sha256": "…" }, { "path": "…", "sha256": "…" }] }; the existing pilot-report input remains required. Only the fixed model-specific list is executed; setup, null-case and out-of-list requests are refused before reservation/provider entry.

Recovery requires the same existing full ledger. Its original header, entry prefix, charges, holds and stop state are retained. An explicit audited recoveryLineage binds the fixed source/host, original report hashes, prior entry count/charged amount and canonical original-ledger hash. These hashes use SHA256 of JavaScript JSON.stringify on the parsed object. The host reads and validates the lineage but never creates or transitions it. Missing or changed history fails closed; a new empty ledger cannot substitute for it. The same $3.75 reservation ceiling, settled-spend $2.80 stop, unknown holds and no-repeat admission continue to apply across every old and new entry. Ordinary pilot/full gates remain unchanged.
