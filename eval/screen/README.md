# Questions about a shared meeting window

Run `npm run eval:screen` with the project's `INCARNAMIND_EVAL_CHAT_KIND`, `INCARNAMIND_EVAL_CHAT_MODEL`, and `INCARNAMIND_EVAL_CHAT_KEY`. The evaluation submits prepared synthetic content through the same in-call Question API as the panel. It loads the production PP-OCRv5 mobile recogniser and compares the Answer with the expected figure or category. It also records whether a picture went with the Question, the Citation checks, local OCR time, and the elapsed time until the first visible Answer text.

The 20 720p frames in `frames.ts` include English and Simplified Chinese slides, spreadsheet rows, labelled charts, an unlabelled bar chart, a process diagram, and two reduced-resolution slides enlarged as a screen share might be. On a machine without the listed Chinese fonts, set `INCARNAMIND_SCREEN_CJK_FONT` to an installed Simplified Chinese font file. Set `INCARNAMIND_SCREEN_CASES` to comma-separated one-based case numbers for a subset and `INCARNAMIND_SCREEN_RESULTS` to a JSONL output path to keep individual replies. The normal run uses all 20.

On 2026-11-22 the direct Anthropic project key returned a credit error. Claude Haiku 5.5 through OpenRouter answered 20/20, including the tallest bar and the next step in the Chinese diagram. Eighteen Questions used text only. The two visual Questions started returning visible Answer text after 782 and 794 ms. Over the full set the median was 598 ms and the maximum was 911 ms. Local OCR took a median of 174 ms and a maximum of 240 ms on the test Mac. Frames were settled before asking. These timings start when the Question is submitted and exclude screen-share network and capture-settling time.

Two additional calls sent a 720p slide, an English spreadsheet and a Chinese spreadsheet between independent WebRTC peers on the same Mac. A separate Chromium profile sent the frames. IncarnaMind captured a dedicated Electron receiver window, ran its native OCR utility and answered through Claude Haiku 5.5. The receiver decoded 126 and 147 frames respectively. All six replies gave the correct figure with a checked screen Citation. Complete replies took 2.7–5.9 seconds across both calls. This duration includes generating and checking the reply.

Across the two 49–60 second sharing intervals the Electron process tree used 3.86% and 3.99% of the 12-logical-core Mac’s total capacity. Expressed in single-core units, the totals were 46.3% and 47.9%. The same running call before capture used 7.2% and 8.8% of one core. The measurement includes receiving the call, capturing three slide changes, recognising text and answering. The second run also measured the final 30 seconds with a static slide at 28.0% of one core. These were local WebRTC calls with test content.
