# Privacy

What IncarnaMind sends from your computer, to whom, and how to stop it. **Settings → Privacy** in the app lists the same, live, and lets you stop each flow on its own.

Your files are read, searched and indexed on this computer. Two things send anything out:

1. **A service you chose** receives what a feature needs to work, and choosing the service is allowing it. Where you choose one, a line says what goes to it ("When you use it, {service} receives…"). Nothing goes to a service you haven't allowed.
2. **A few connections carry nothing of yours**: update checks, model downloads and sign-ins. They are listed below and in Settings → Privacy.

With **Keep everything on this computer** (local mode) on, only a model on this computer is used, and what it still allows is listed in [Local mode](#local-mode). Background work never asks: a flow you haven't allowed waits, and says so where its status shows.

Choosing the AI model's provider (in first-run setup, in Settings → Models, or by signing in with your ChatGPT plan, your Claude account, or GitHub for your Copilot plan) allows Chat, Edit with AI, the checks and Writing suggestions at once, so none of them asks again. Checking a sentence against a chosen Document or Folder is separate: it asks before its whole read. Tagging and sorting Documents, and page images of scans, are not among them either: you turn them on or ask for them. Choosing a service again is a new choice and replaces an earlier "Don't allow". A flow asks again only when it starts sending something its line didn't name, and a provider you chose before this rule asks once, at the first send, for a flow it never asked about.

### What these flows have in common

- **Document and Note names go out.** Every Question sends up to 50 Document names, a Question in the assistant the names of up to 30 of your Notes when its model can read them, and the Passages it sends carry their Documents' names and pages; Organize, Library grouping and Automatic Tags send each Document's name. Folder and Tag names and descriptions go with those two flows too.
- **Meetings use the chat flow.** The call help panel (on by default) asks an Answer with the Note's AI model when you press a help button: it sends the Note, the newest live Transcript lines (about 8,000 tokens, "Me" and "Them"), Passages from the Note's Folder, and Document names. Any Question asked in that Note while recording takes the live Transcript too. After Stop, the note is filled in from the whole Transcript (up to about 24,000 tokens a run) and its claims are checked against the Folder; neither asks again once the chat flow is allowed, and both are off in local mode.
- **Find sources asks once per provider**, before its first request; one you don't allow is never sent anything. openFDA, DailyMed and ClinicalTrials.gov, for drug labels and clinical trials, are searched only when you choose them (or type an NCT number), and are sent the drug, condition or number you typed. If you add your own openFDA key, it is kept in your keychain and sent only to openFDA, in a header. The eCFR, for US federal regulations, is searched only when you choose it, and is sent the words you typed; a citation you type (such as 17 CFR 240.10b-5 or 42 U.S.C. § 1983) is sent to the eCFR and to GovInfo. GovInfo is used only once you add your own free api.data.gov key: the key is kept in your keychain and sent only to GovInfo's API, in a header, and GovInfo asks first, saying so.
- **Research tasks** use Connectors, web search and Find sources as an Answer does, under the same consents.
- **Providers are asked not to store your requests** where they offer that. IncarnaMind can't make them.

## Connections that carry nothing of yours

These are listed in Settings → Privacy under "Other network traffic".

- **Update checks** (`update-check`) go to GitHub Releases once at startup in a packaged app. On by default; turn them off in Settings → Privacy.
- **Model downloads**: the search model (`embedding-model`), the result-ordering model (`reranking-model`), the text recognition model (`text-recognition-model`, 21 MB) and the speech model with the two models that tell a Meeting's speakers apart (`transcription-model`; the speaker models are about 30 MB) come from huggingface.co, once, when a feature first needs them: the speech and speaker models when you first record a Meeting. When huggingface.co can't be reached, the same files come from hf-mirror.com (`model-source-hf-mirror`) or from IncarnaMind's own copies on ModelScope (`model-source-modelscope`) and Cloudflare R2 (`model-source-copy`), once those are set up. Before a model downloads, a request with nothing in it goes to huggingface.co and hf-mirror.com at once (to www.modelscope.cn instead, once IncarnaMind's copy there exists), to see which answers first; it is asked again after 10 minutes and whenever the system proxy changes. Model downloads send no cookies, follow a redirect only to the source's own hosts and never from https to plain http, and every file is checked against the size and SHA-256 IncarnaMind records for it, whichever host it came from. Each is a plain download of a fixed file: nothing of yours is sent. Ollama pulls (`ollama-pull`) come from Ollama's registry, when you pick local models.
- **Sign-ins**: ChatGPT (`chatgpt-sign-in`), a Claude account (`claude-sign-in`, experimental, off unless you choose it) and GitHub for Copilot (`copilot-sign-in`), and keeping them renewed. A Claude account sign-in goes to Anthropic's sign-in pages and token service. A GitHub sign-in goes to github.com: the ID of the app signing you in, then, while you approve on GitHub's page, the device code GitHub gave it, and later the refresh token that renews the sign-in. Once you've approved, your GitHub token goes once to api.github.com to read your account's name, which Settings → Models shows and IncarnaMind forgets when you sign out. Questions asked with your Copilot plan, and the request for the models your plan offers, go to api.githubcopilot.com with your sign-in's token, under your account and your plan's limits. On the experimental way, your GitHub token also goes to api.github.com, which trades it for a short-lived Copilot token and says which plan you have. Settings → Privacy lists each address a sign-in reaches.
- **Remote Connectors** (`remote-connectors`): connecting to each remote Connector that is on, and signing in to it: its server, and the authorization server it names. The Tool calls, which carry your content, are the Connectors flow above.
- **Usage data** (`usage-data`): only if you agree; see [Usage data](#usage-data). A test build for invited testers sends until you turn it off.
- **Crash reports**: off unless you turn them on in Settings → Privacy, and stripped of your content first.

## Web pages

Web pages you add are fetched from your computer, straight from their site, when you add one and when you choose Fetch again, with the article's pictures, which may come from the site's image servers: anonymously, without cookies, and never from your computer or your local network. The site sees the request, and the address itself can name a matter. Each picture's address is kept with the page, beside the picture, as the page's own is, for Fetch again. Nothing else on the page is loaded: not its other pictures, ads, scripts or trackers. The address is fetched from your computer, not through an IncarnaMind server. In local mode a page you name isn't fetched: a line says it would contact the site, with "Fetch this page once" to let that one page go (local mode stays on) and "Don't fetch". That holds for Fetch again too. Pages already added keep working, and a page saved from a file you dropped in, or from a page open in the app, is not fetched at all.

Only if you tick "Keep the page as it looks" when you add it, or turn it on in Settings → Search → Saved web pages (off unless you do), is the page also loaded once more as a browser would load it, scripts and all, in a hidden page that keeps no cookies and reaches only the public internet, never your computer or your local network, to keep a PDF of how it looked: the sites it draws from then see a visit, as they would if you opened it. In local mode no page is loaded this way, whatever was ticked or set: the page shows "Not kept as it looks" with Try again for when the setting is off, and a look that was waiting when the app quit is dropped the same way. A page an Answer's web search saves is never loaded this way. An open-access copy of a work you add with Find sources is downloaded once, without cookies, from the publisher's or repository's site: only its address is requested.

## Local mode

**Keep everything on this computer** (Settings → Privacy) stops every flow in the table above except with a model on this computer, turns usage data off and keeps it off, pauses remote Connectors and every agent, switches cloud embeddings to the built-in model and removes the cloud embedding key. A cloud model is refused up front, and every request is also checked when it is sent. Page images and Meeting audio never go in local mode.

Web pages by address are held until you let each go (see [Web pages](#web-pages)). What local mode does not stop:

- **Update checks** to GitHub at startup, unless you turned them off.
- **Model downloads** from huggingface.co, hf-mirror.com and IncarnaMind's own copies, with the request to huggingface.co and hf-mirror.com (www.modelscope.cn once IncarnaMind's copy there exists) that picks between them, and Ollama pulls, when you ask for a model. They send nothing of yours, so local mode doesn't stop them; the speaker models download when you first record a Meeting, without asking.
- **A Connector on this computer** keeps working, and can reach the network itself. Only one whose sign-in is with a server on another computer is paused: its sign-in isn't renewed or started, its Tools aren't offered, and it goes on from where it was once the setting is off. A remote Connector whose server isn't on your computer is paused entirely, its sign-in included.
- **Crash reports**, once you turned them on in Settings → Privacy; they are stripped of your content first.

## Other things that leave, or never do

- **AI agents you connect** (off by default): an agent you run yourself, such as Claude Code or Codex, can search and read the Documents and Notes in the folders you share with it, and ask IncarnaMind Questions. What it reads goes on to the AI model the agent uses, under that service's terms, not IncarnaMind's; some consumer plans may use it to train their models. You approve each pairing, and Settings → Privacy lists it. IncarnaMind keeps its pairing key in the protected secrets store described below, but unlike other keys, a copy is in plain text in the agent's own settings, copied setup command or install bundle. Any process running under your account can read that copy: keep it private and never paste it into a conversation. Activity keeps up to 500 calls per agent on this computer, including search words, tool names, outcomes and the Documents read. Disconnect stops access immediately, revokes and removes IncarnaMind's key, and removes the agent's Activity from the app by marking its rows deleted; their summaries remain in the local database. Copied commands and agent settings can retain the revoked key, which no longer works. On the first start after upgrading from an earlier alpha, existing pairings stay saved but connections wait until you turn agents on again in Settings. How to connect each agent: [agents.md](agents.md).
- **The built-in models' runtime** (Microsoft's ONNX Runtime) runs with its usage telemetry turned off in every engine, speech included, on every platform. In the installed app on Windows the speech engine loads the same runtime as the others; on macOS and Linux it has its own copy, which reads the same switch. It makes no connection of its own and, on Windows, keeps no folder. Up to 0.1.0-alpha.4 the runtime's reporting was on everywhere: on macOS and Linux it sent Microsoft directly a random device id (hashed), a Mac's model, your operating system and its version, your CPU's name, core count and memory, the name of each model file (not its folder) with the model's hashes and metadata, whether it ran on the CPU or the GPU, counts and timings of its runs, the process's peak memory and CPU time, and its error codes and messages with file paths cut out; on Windows it wrote the model file's name, hashes and metadata, your CPU's name, core count and memory, your graphics card's and NPU's names and driver versions, whether it ran on the CPU or the GPU, counts and timings of its runs, and error codes and messages with file paths cut out, to Windows' diagnostic data. Through 0.1.0-alpha.5 the speech engine's own copy of the runtime on Windows still wrote its events there, and its error events kept file paths, which on Windows contain your user name; your Windows privacy settings decided whether they left the computer. Microsoft's model runtime keeps usage data in a folder on this computer, and earlier versions of IncarnaMind may have added to it. It is safe to delete: `~/Library/Application Support/Microsoft/DeveloperTools/.onnxruntime` on macOS, and `~/.cache/Microsoft/DeveloperTools/.onnxruntime` on Linux, or the same folder under `$XDG_CACHE_HOME` when that is an absolute path. On Windows the runtime keeps no folder. While the folder is there on an install that earlier versions ran on, Settings → Privacy says so and offers to show it. IncarnaMind never reads what is in it.
- **Meeting audio is kept on this computer** for 24 hours after the last stretch, then deleted. The Transcript is kept as a Document. No screen video is captured.
- **The AI use record** stays on this computer and is never sent, whatever you choose about usage data. It notes each time the AI wrote into a Note and what you did with it, and each sentence a model checked, as sizes, kinds, the model's name and times, with no text. Clear it in Settings → Privacy. "Export AI use statement" in a Note's menu turns it, with the Note's own AI text marks and checks, into counts in a new Note on this computer, for you to edit and attach to a thesis; nothing is sent.
- **The cost record** stays on this computer and is never sent. For each request to a cloud model it notes the model, the tokens its provider reported and what that cost at its price, with no text, for this month's figure and the monthly cap in Settings → General.
- **A Word file you import as a Note** is read on this computer and sends nothing. A copy of it is kept in your data folder ("Word imports"), so export can write your changes back into it after the file has moved; it is deleted once no Note made from it is left, Recently deleted included.
- **Check comments on a Word file someone else wrote** quote your Documents and name them, and go in the file you return, when you ask for them.
- **A web page to share** (an export format) is written on this computer like any export, and nothing is uploaded: you send the file yourself. Besides the Note, it holds each Citation's quote and the passage of its Document around it, and, for a PDF, a scan or a slide, a picture of the part of the page around the quote (at most a third of a page) or of the slide, taken from the page saved when the Citation was made; never a whole Document. Anyone you send it to can read those. In the export options you can keep a Document's Citations as text, without pictures. The page loads nothing when it is opened.
- **Skill scripts** run on this computer and can send what they read. Each script asks before it runs, unless you set it to Always allow in Settings → Privacy (Approvals).

## Your keys and the logs

- **Keys** are encrypted by Electron's `safeStorage`, whose key is held by the macOS Keychain, Windows DPAPI, or GNOME Keyring or KWallet on Linux. The encrypted keys sit in `secrets.json` in your data folder (readable only by your account), never in the database. On Linux with no keyring, saving a key is refused until you accept plain-text storage on that device; after that the keys are encrypted with Chromium's fixed key, which is effectively plain text. With no encryption available at all, saving is refused. A key leaves only to its own service. A provider with a China and an International region (Kimi, Qwen, GLM, SiliconFlow) gets the key, its test and every request only on the region you pick: api.moonshot.cn or api.moonshot.ai, dashscope.aliyuncs.com or dashscope-intl.aliyuncs.com, open.bigmodel.cn or api.z.ai, api.siliconflow.cn or api.siliconflow.com. Nothing tries the other region for you: when yours refuses the key, the same key goes to the other region only if you press "Send it to …" under the refusal. Adding a provider tests its key with one short message to that provider ("Reply with the word OK."); in local mode that test isn't sent, the key is kept, and a line says it was saved but not checked. It is checked the first time it is used once local mode is off. The OpenAI key also goes to OpenAI for cloud transcription, the Qwen key to the chosen region's DashScope host for Qwen cloud transcription, and a Soniox key goes to api.soniox.com to be checked. An openFDA or GovInfo key is sent only to that service, in a header.
- **The log** holds ids, statuses and kinds, not your content, with one exception. When an Answer fails it also keeps the HTTP status and the first line of the failure's message, so the cause can be found. That message is the provider's own words, or IncarnaMind's own when the failure is local (a Skill that can't be opened, for example), and the log file cuts it to 200 characters. Before it is kept, anything in quotes (and everything from a quote that is never closed), anything that looks like a key, and every key IncarnaMind has handled are taken out. A provider rarely repeats what it was sent. What it repeats in quotes is taken out, but words it repeats without quotes are not. The log file and crash reports (if you turned them on) pass a filter that strips strings that look like keys.
- **There is no sync.** Nothing is uploaded to an IncarnaMind account; there isn't one.

## Usage data

Usage data is a small set of anonymous product events, such as "a Question was asked with a local model" or "an Answer took 6 seconds and has 3 Citations, each quote found". It shows which features are used and where people get stuck. It never holds your files or what you write.

### When it's sent

- **Only from a build made with an analytics project.** A build without one (from source, by default) sends nothing, asks nothing, and doesn't load the analytics code.
- **A release asks once, after the first Answer to a Question of your own,** in a card at the bottom of the sidebar, not on the first run. Nothing is sent, or kept to send, unless you choose Send; the default is no.
- **A test build, for invited testers,** sends usage data until you turn it off, as testers agree to when they join. Its first run says so, in a notice at the bottom of the sidebar with the switch to turn it off.
- **Local mode** ("Keep everything on this computer", in Settings → Privacy) turns usage data off, and it stays off.
- **You can change it any time** in Settings → Privacy, under "Usage data". Turning it off stops sending at once and drops anything still waiting to be sent.

### What's never sent

Your Documents, their text or names, Folder and Tag names, Questions, Answers, quotes, your text, API keys, file paths, the names of Connectors or Skills you added, an account, an e-mail address, your device's serial number, your IP address or your location. Nothing is recorded automatically: there is no session replay, and no capture of clicks or typing. Every event is sent explicitly by the app's code.

### How it's sent

Events go to [PostHog](https://posthog.com), an open-source analytics service, to the project the maintainer set in the build (PostHog's EU cloud or a self-hosted server), using PostHog's open-source Node.js library in the app's main process. The window never talks to the network itself.

- Each event carries a random install ID, made the first time an event is sent. It lets one install's steps be followed, and nothing else. **Reset install ID** in Settings → Privacy gives a new one.
- No person profile is made, no location is looked up, and PostHog stores `0.0.0.0` instead of your IP address.
- Events wait in a short queue in memory (at most 100), and are sent together every 30 seconds or every 20 events. If a send fails, for example offline, those events are dropped. Nothing is written to disk.

### Every event

Every field is a value from a closed list, a whole number, or true/false: there's no field for text. The app checks each event against this list before it's sent ([`src/core/usageEvents.ts`](../src/core/usageEvents.ts)), and nothing else can be sent.

| Event | Fields |
| --- | --- |
| `app_opened` | `language`: the interface language, `en` or `zh-CN` |
| `example_opened` | `group`: which example was opened from an example's banner: `tea`, `papers`, `reports`, `contracts` or `meetings`. Nothing else |
| `mind_created` | No fields: you made a Note |
| `question_asked` | `provider`: the kind of provider of the model (`openai`, `anthropic`, `google`, `deepseek`, `qwen`, `kimi`, `glm`, `siliconflow`, `mistral`, `xai`, `openrouter`, `openai-compatible`, `ollama`, `chatgpt`, `claude-account`, `copilot`); `local`: whether the model runs on your computer. Never the Question or the model's prompt |
| `answer_finished` | `outcome`: `done` or `stopped`; `duration_ms`: how long it took; `citations`: how many Citations it has; `found`, `not_found`, `cant_check`: how many of them by check |
| `citation_opened` | `check`: the Citation's check, `found`, `not-found`, `unsupported`, `contradicted`, `cant-check` or `checking` |
| `documents_added` | `documents`: how many new Documents; `already_added`: files that were in already; `skipped`: files that couldn't be added; `pdf`, `docx`, `pptx`, `xlsx`, `csv`, `markdown`, `text`, `web`, `transcript`: the new Documents by format (`web`: web pages saved by their address; `transcript`: WebVTT Transcripts, a Meeting's or a file's). Never their names or addresses |
| `folder_linked` | No fields: you linked a folder. Never its name or path |
| `organize_run` | `documents`: how many Documents; `all`: whether it was all of them; `model`: the kind of model, `chat`, `jev`, `auto` or `ollama` |
| `mind_exported` | `format`: `markdown`, `docx`, `pdf`, `source-pack`, `html` or `share-page` (a web page to share); `questions`: whether Questions were included |
| `connector_used` | `remote`: whether the Connector is remote. Sent once per Connector and Answer. Never its name: every Connector is one you added |
| `skill_used` | `skill`: a built-in Skill's name (`chronology`, `cim-red-flags`, `covenant-summary`, `credit-memo-outline`, `deposition-summary`, `earnings-review`, `literature-review`, `mind-to-report`, `summarise-document`), or `own` for one you added, whatever its name; `forced`: whether the Question asked for it. Sent once per Skill and Answer |
| `error_occurred` | `area`: `answer`, `document` or `connector`; `kind`: the kind of error, such as `rate-limit`, `password-protected`, `forms-unread` or `timed-out`. Never its message |
| `settings_page_viewed` | `page`: which page of Settings, such as `privacy` |

Every event also carries:

| Field | Value |
| --- | --- |
| `app_version` | The app's version, e.g. `0.1.0` |
| `os` | `darwin`, `win32`, `linux` or `other` |
| `arch` | `arm64`, `x64` or `other` |
| `build` | `release`, or `tester` for a test build |

And PostHog's library adds the same values to every event: `$process_person_profile: false` (no person profile), `$geoip_disable: true` (no location), `$ip: "0.0.0.0"` (no IP address), and `$lib` and `$lib_version` (the library's name and version).

### For maintainers

A build sends usage data only when it's built with both of these set (electron-vite reads them from the environment or a `.env.local` file, never from the code):

- `MAIN_VITE_POSTHOG_KEY`: the PostHog project's API key (`phc_…`), which can only send events.
- `MAIN_VITE_POSTHOG_HOST`: the project's host, over https, e.g. `https://eu.i.posthog.com` or a self-hosted server.

`MAIN_VITE_TESTER_BUILD=1` makes a test build, where usage data is on until the User turns it off. The release workflow sets it only for tags with `-tester` in them (`v0.9.0-tester.1`); an `-alpha` or `-beta` tag makes a release build, which asks first. See [releasing.md](releasing.md).

In the PostHog project, turn on **Discard client IP data** too (it's the default for organisations in the EU cloud).
