# Citation styles are formatted by Hayagriva, built to wasm

Citation styles and a styled Bibliography (#289) need a CSL processor: APA 7, IEEE and GB/T 7714 (2015 and 2025) for the alpha, and any CSL style a User brings. The JavaScript processors break our dependency rule (`AGENTS.md`: open source under a permissive licence, maintained, small). citeproc-js is CPAL-1.0 or AGPL-3.0, and citeproc-rs is MPL-2.0 and archived. The spike in #288 built Hayagriva, the CSL engine in Typst (MIT or Apache-2.0), to WebAssembly and compared it with the citeproc-js that Zotero ships, on 30 English and Chinese references in 11 styles. The full report is [0024-citation-styles-spike-report.md](0024-citation-styles-spike-report.md).

We format citations with **Hayagriva, compiled to wasm with a small binding of our own**.

## The engine and its binding

- **The engine.** Hayagriva with its default features off and `csl-json` on, pinned to a commit of its `main` branch (`546c7c7`) until a release carries the fixes we need. The latest release, 0.10.1, drops every author in the Vancouver style. We fix the Hayagriva bugs the spike found (the report lists them) in Hayagriva itself, not in our copy, and the pin moves to a release once one carries them.
- **The Rust binding** (about 240 lines) takes the style and locale XML and the references as CSL JSON (the shape #286's reference record converts to) and returns the citations and the Bibliography as **runs**: text with italic, bold, small caps, superscript, subscript and link flags. It speaks JSON over the module's memory without wasm-bindgen (one build tool and five crates fewer, and no generated JavaScript to keep in step with a CLI version); `src/core/citationStyles/wasm.ts` is its loader. A run says which of the citation's references it writes (`item`), so the editor can tell Citations apart inside a cluster. The binding the app ships offers no HTML mode, because Hayagriva's HTML doesn't escape field text and reference metadata comes from files and lookups we don't control: the text is only ever text.
- **What the binding adds is TypeScript,** in `src/core/citationStyles/format.ts`, so it changes without a rebuild:
  - Chinese runs are never italic, as in Zotero.
  - No space between a Chinese name and 等 ("(钱学森等, 1990)", "林衍凯，等"), as Zotero's citeproc-js writes it, which most Chinese academics cite with.
  - In a GB/T style a reference that isn't Chinese is written with English terms ("et al." with its space, "4th ed."). Hayagriva's per-item locale changes no terms, so this is two renders, the style's locale and `en-US`, each entry and each cited reference taken from the render in its own language. It gives what the styles' CSL-M layout gives in citeproc-js, which Hayagriva can't read.
  - A work cited twice in one cluster is cited once, its Locations together, so a cluster never reads "[1,1]".
  - A style whose file prints no Locator while its standard prints one outside the citation says so (`CitationStyle.locators`, "raised-after" for the four GB/T styles). Each work with a Location in such a cluster is then cited on its own, its Location raised after it ("[3]⁵⁻⁶"), as GB/T 7714—2015 10.1.3 and 10.2.5 print them. A style brought in later says which it is the same way.
  - Rich-text markup in fields needs nothing yet: reference records (#286) keep fields as plain text, and the import (#287) strips markup.
- **Behind an interface in the core.** A `CitationStyleEngine` in `src/core` hides the engine, as `RunEngine` hides the agent loop (ADR-0007). It runs on its own worker thread (`styleWorker.ts`), which loads the module and the locales once, parses each style once, and is started again after a crash. The core keeps the last answers, and the editor asks again only when the Citations, a cited record or the style change. Formatting 30 references takes 3–70 ms warm and 300 references up to 0.75 s, so markers update when formatting finishes, not on every keystroke.

## How it is built and shipped (#289)

- **The built engine is committed; CI shows it reproduces.** `resources/citation-styles/engine.wasm` is committed with its SHA-256, built by `wasm/citation-styles/build.sh` from the binding there, with a pinned Rust (1.99.0), `Cargo.lock`, Hayagriva at `546c7c7` and binaryen's `wasm-opt` 132. The script remaps local paths out of the module. The committed file is the build on x86_64 Linux, the platform of CI's runners: cargo mixes the build machine's platform into the hashes of every crate that uses a procedural macro, so a Mac builds a module that works the same but differs in bytes. `npm ci` and the app's build need no Rust; only a change to the engine does. A workflow (`citation-engine.yml`) rebuilds it with `--check` whenever the binding or the file changes and uploads what it built, which is the file to commit after a change to the binding. A unit test checks the file against its checksum.
- **Built for speed:** `opt-level = 3` and `wasm-opt -O3` give 2,549,995 bytes (850,304 gzipped), and the heavy styles format about 30% faster than with the size-optimised build.
- **The styles** are every style of the CSL styles repository and every locale of its locales repository, at pinned commits, unmodified in one pack, `resources/citation-styles/styles.pack` (2,863 styles and 8,002 journal styles on 2026-10-15).
  - Each file is kept byte for byte, its `<info>` untouched, and named in the licence notice with the CSL project, a link to citationstyles.org, each style's title and authors, and the CC BY-SA 3.0 licence. Shipped this way they are a "Collection" under CC BY-SA 3.0 (§1(b)), so share-alike covers the style files and IncarnaMind stays Apache-2.0. If we ever change a style, the changed file is shared under CC BY-SA.
  - The files are compressed with brotli (Node's `zlib`, no new dependency) in chunks of about 50 behind an index, so opening a style decompresses its chunk alone: 2.6 MB in all, against 62 MB as files. `scripts/citationStylePack.ts` (`npm run styles:pack`) builds it; `--check` rebuilds and compares.
  - **Checked when built:** every style is parsed by our engine and formats one reference; one that fails is left out, with the journal styles that follow it, and the build names each. A test keeps the count above a floor, so an engine update can't drop hundreds unnoticed.
  - **A journal style is an alias:** its id, title, fields and default-locale, and the style it follows, whose file it formats with. A style with no default-locale formats in the Mind's language: zh-CN for a Chinese Mind, otherwise en-US. The common styles keep their own language.
  - **Read only when needed:** the first time the picker opens or a Mind in a style other than Numbered is formatted. A first run and a Numbered Mind never touch the pack.
  - **The licence notice is generated** from every style's and locale's `<info>`, ships in the pack, and Settings › About opens it; `resources/notices/citation-styles.txt` points to it.
  - **Moving to newer styles:** set `STYLES_COMMIT` and `LOCALES_COMMIT` in `scripts/citationStylePack.ts`, run `npm run styles:pack`, and read the styles it says it left out. Raise or lower the floor in `tests/core/citationStyleFiles.test.ts` if the count moved, check the goldens' diff for the common styles, and commit `styles.pack`, its `.sha256` and `resources/notices/citation-styles.txt` together.
  - **A Mind keeps a style a later pack no longer has,** and is formatted as Numbered, the style's place saying it isn't available in this version.

## Which style a Mind uses

- **Numbered** stays as IncarnaMind's own form beside the CSL styles: numbered markers, and footnotes naming the Document and its Location. It is the default for every Mind that hasn't chosen: many Minds cite contracts and reports with no reference record, which a CSL style would only turn into "(n.d.)". The References block shows only once a Mind is in a style other than Numbered. A Numbered Mind shows it as its Bibliography once "/" Bibliography asks (#102): each Document once, by name, with the Locations cited.
- **A Mind that cites a paper or a book** offers a style in one line at its end, the interface language's own first (APA in English, GB/T 7714 in Chinese), until the User picks one or closes the offer for that Mind. "A paper or a book" means a reference record of kind article-journal, paper-conference, article (a preprint), chapter, book or thesis, with its authors or a year. A report, a web page or Other (an agreement, a statement) never counts, whatever its authors or date. The kind is the Library's reference record, never a guess from the file's look.
- **Chinese theses (#706).** A Mind that hasn't chosen is in GB/T 7714—2015 (numeric) when the interface is Chinese, its text is Chinese and it cites a paper or a book. Every other Mind is Numbered: one citing only contracts and reports in Chinese never turns into a list of entries needing details. It never replaces a style the User chose. The first time it applies, the undo line says so once, "此 Mind 引用了论文，引用格式已设为 GB/T 7714—2015（顺序编码制）· 更改 · 撤销", and never again in that Mind; Undo makes Numbered the Mind's own choice. The References header says "默认" beside the style, and Export options says why.
- **The style chosen for a Mind in a Folder** is the one new Minds in that Folder start in (`library_groups.citation_style`, migration 52).
- **A record with nothing to cite it by** is listed by its name alone; its format and the day it was added are no bibliographic facts. **No placeholder goes into an exported file** (#1910): an entry too thin to cite is written with the details its record has. The Saved line under the file says once how many Documents lack authors or dates, "2 Documents lack authors or dates · Add details" ("2 个文档缺少作者或日期 · 补充信息"), and Add details goes to the first of them in the Mind's References.

## Considered options

- **(B) A written exception for citeproc-js (CPAL-1.0 or AGPL-3.0) or citeproc-rs (MPL-2.0).** citeproc-js is what Zotero runs, so its output would match Zotero by definition, and it supports CSL-M. Rejected. AGPL would put the app under copyleft. CPAL's §15 treats network use as distribution, which would bind the hosted version (ADR-0002) to publish its source, and §14 lets the author require an attribution display at every start. citeproc-rs is MPL-2.0, which we could live with, but it has been archived since 2024, so nobody would fix it.
- **(C) A few hand-written styles** (APA, IEEE, GB/T 2015 and 2025). No licence question, but each style is hundreds of rules (disambiguation, et al., name forms, year suffixes, sorting, locale terms) that we would own, and Users couldn't use the style their university hands out. Rejected as the main route; it stays the fallback, behind the same interface, if Hayagriva stops being maintained.
- **A community wasm build of Hayagriva from npm** (`citeme-engine-wasm`, `refkit-js`). Both are months old with one maintainer each. Owning 240 lines of binding is less risk.
- **Building the wasm in CI on every run.** It would put rustup and a two-minute build in front of every contributor's tests, for a file that changes a few times a year.

## Consequences

- **Output differs from Zotero in known ways until the upstream fixes land.** On the spike's fixtures, 90% of citations and 82% of Bibliography entries match Zotero exactly. The report lists every difference, and #289's golden tests record our expected output per style, so a Hayagriva update shows exactly what changed.
- **Licence notices grow:** the 58 crates linked into the wasm (MIT, Apache-2.0, Unicode-3.0, BSL-1.0 and other permissive licences; none copyleft) and the CSL styles and locales with their attribution.
- **Hayagriva's maintainers say it is under-maintained** (typst/hayagriva#460), and it has no CSL-M. Typst depends on it, and fixes do land, but we should expect to write some of them. The interface keeps option (C) open.
- **A User's own CSL file** goes through the same engine, so a style that only citeproc-js handles well may come out differently. #289 shows the problem where it happens, with the style named.
