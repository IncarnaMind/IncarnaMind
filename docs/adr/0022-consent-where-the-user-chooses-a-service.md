# Consent is given where the User chooses a service

Nothing leaves the computer for a service the User hasn't chosen. The User chooses a service in one place (first-run setup, Settings, connecting a Connector or an agent, the meeting sheet), and that place says, in one line, what will go to it. Choosing is consenting to that. We don't ask again per feature: the flows that send to the chosen chat model (Answers, Edit with AI, checks, suggestions) are covered by choosing it. Two kinds of work are not, and each has its own switch (below).

- **Asked again** only when a flow starts sending a kind of data its line didn't name.
- **Asked in place** for a service the User didn't pick (reference look-up), once, where the feature starts.
- **Tagging and sorting new Documents by themselves are their own switch** (Settings › Tagging): off for a cloud model, on for one on this computer. They send each new Document's name and an excerpt without the User asking, so choosing the chat model does not allow them; turning the switch on does, and records it in Settings › Privacy. This changes the earlier rule, under which choosing the model covered Tags and organization. Organize and Re-tag asked for by hand still go.
- **Page images are their own switch.** Organize reading a scan with no text sends its page pictures, which carry more than the text the chat line names, so choosing the chat model does not allow them: the User allows them per service, in Settings › Privacy or from the Document's Info. This changes the earlier rule, under which choosing the model covered them.
- **Never asked by background work,** which waits and says so.
- **Revocable per flow** in Settings › Privacy, which lists every flow, the service it goes to and when it was allowed.
- **Local mode** sends nothing to any cloud service, whatever was chosen.

Considered: a dialog per flow and service (the previous rule), rejected after persona testing found two or three dialogs in the first minute; one dialog per provider at the first send, rejected because the User has already chosen the provider a moment before and the dialog only repeats it.

## Amendment: choosing a model for Tags turns the switch on (2026-10-31, #2308)

Choosing a cloud model for Tags turns **Tag and sort new Documents automatically** on in three places: first-run setup's third step ("Use this"), Settings › Tagging (a model's row, or Other model… once saved), and Settings › Models' sorting row, whose Turn on… is shown while the switch is off. In each, before the choice, a line on screen says what each new Document sends and to which service. It sends the Document's name and type and an excerpt of its start (about 1,500 tokens), with the Tags' and Folders' names and descriptions, in Settings › Privacy's words. The line says that a Linked folder's new Documents go too, and that Documents already in the Library go only when the User runs Organize.

- **Only what is new goes by itself, per service.** Automatic tagging and Organize send a Document to a service by themselves only if tagging was turned on for that service itself, and IncarnaMind saw the Document arrive new after that, or the User's own Organize or re-tag already sent it to that same service. Arriving new means the User added it, or linked its folder then, or the folder's watcher reported it after the folder's first scan; a cloud drive's placeholder that downloads later was there before. A file's own times count for nothing. Both senders check this on the service the request actually resolved to, just before they send. Organize is checked on its own model's service; a scan's page images, which may go to the image model's service instead, pass a separate gate: the scan-images consent the User gives for that service. Re-tag all is the User's own request for every Document in the places where tagging is on and not stopped, those held since before the turn-on included; while tagging reads off for where it sends, it sends nothing and leaves every Document as it was, and the switch's line asks for the turn-on. Re-tagging chosen Documents, or one Folder, is the User's own request for them. Everything else waits, "off", for the User to run Organize or a re-tag: an edit, a save by rename, a copy keeping its date, a file found by a later scan (a resume, a restart), one restored from Recently deleted, or one read again.
- **It is on for where it sends.** Turning it on is the consent for the services it sends to then, recorded with its time, and only these three places turn it on, with the line on screen. Any other save can only turn it off, so a window with an older view never turns it back on. On for a model on this computer, or for one service, isn't on for another: when where it sends changes, it reads off until the User turns it on there.
- **Settings › Models turns it on only through Turn on….** Changing the sorting model there never turns it on, and it reads off when the new model sends somewhere it wasn't turned on for. While the switch is off, the row says "Tagging new Documents is off · Turn on…". Turn on… shows the same line, and only its Use this turns tagging on; Cancel or Esc leaves it off. ⌘K's "Turn on tagging new Documents…" opens it.
- **The chat model for Answers doesn't turn it on.** Choosing it still doesn't.
- **Existing profiles keep their switch.** A profile that chose a model before this rule keeps its switch as it was. No migration or default turns it on, and a save that shows the switch off keeps it off.

Before, a User who chose "Tags and Folders use Claude Haiku 5.5" in setup got no Tags at all, with every Document "off" and nothing saying why.

## Amendment: dropped Documents ask on their own row (2026-11-04, #2308)

The User found scans they dropped left in no Folder, with nothing saying why. With a cloud model, sorting new Documents by itself is off until it is turned on for that service, and the only way to turn it on was in Settings. Now the Documents waiting say so where the User sees the Library's work, and the User can allow it there.

- **Nothing goes before the press.** Without the switch on for the service Organize sends to, a dropped Document stays in no Folder and nothing of it is sent. Its first pages are still read first, on this computer either way.
- **The press is the consent, for that service only.** The sidebar's footer says "4 to organize · Allow {service}", its popover says what is sent before the press ("…sends each Document’s name, kind and page count, the start of its text and its slide titles or sheet names, with your Folders’ names and descriptions and any matching Tags’, to {service}, for these and for Documents you add later"; page images aren’t named there, since the press doesn’t allow them), and the button names the service. Pressing it records the consent through `src/core/consent.ts` and turns on "Tag and sort new Documents automatically" for that service, as the switch's own Turn on does, with its time.
- **The Documents waiting are organized at the press,** as the User's own Organize, with its one Undo: every Document in no Folder held back this way, older ones included, as the row's count says. The User's request is kept, so a quit before the run ends doesn't lose it. From then on, new Documents go by themselves.
- **The row asks only for one service.** When turning sorting on would turn it on for another service too (tagging's, such as a saved Jev key), no row asks, and nothing goes: the User turns it on in Settings, as before.
- **Turning the switch off withdraws it.** Nothing more goes by itself, and Documents that wait show the row again. Another cloud service asks again on its own row. A model on this computer is unchanged.
- **Walls and Local mode still hold.** A Document filed inside a Folder that keeps its work inside it never goes to a cloud service by itself, and in Local mode the row doesn't show and nothing goes.
- **What one Organize request sends**, as the code builds it: the Document's name and type ("PDF, 46 pages"), the start of its text (its first 6 Passages, cut at about 1,500 tokens), a deck's slide titles or a workbook's sheet names (up to 16, 60 characters each), every Folder's name and description except those the User turned down for it, the name and description of the Tags in the Document's script, and fixed instructions; a scan with no text adds up to 3 page images only where that flow is allowed. When the only Tag given is an Invoice Tag the text doesn't bear out, a second request asks again without it. No path, size, date or language is sent.

This reverses, for sorting, the rule that only setup, Settings › Tagging and Settings › Models turn the switch on: the row's Allow is a fourth place, with the line on screen.
