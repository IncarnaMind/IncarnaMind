# Consent is given where the User chooses a service

Nothing leaves the computer for a service the User hasn't chosen. The User chooses a service in one place (first-run setup, Settings, connecting a Connector or an agent, the meeting sheet), and that place says, in one line, what will go to it. Choosing is consenting to that. We don't ask again per feature: the flows that send to the chosen chat model (Answers, Edit with AI, checks, suggestions) are covered by choosing it. Two kinds of work are not, and each has its own switch (below).

- **Asked again** only when a flow starts sending a kind of data its line didn't name.
- **Asked in place** for a service the User didn't pick (reference look-up), once, where the feature starts.
- **Tagging and sorting new Documents by themselves are their own switch** (Settings › AI, under Organize and Tags): off for a cloud model, on for one on this computer. They send each new Document's name and an excerpt without the User asking, so choosing the chat model does not allow them; turning the switch on does, and records it in Settings › Privacy. Organize and Re-tag asked for by hand still go. (Choosing the model used to cover Tags and organization; it no longer does.)
- **Page images are their own switch.** Organize reading a scan with no text sends its page pictures, which carry more than the text the chat line names, so choosing the chat model does not allow them: the User allows them per service, with "Read scans as page images" under Organize and Tags in Settings › AI, in Settings › Privacy or from the Document's Info. (Choosing the model used to cover them.)
- **Never asked by background work,** which waits and says so.
- **Revocable per flow** in Settings › Privacy, which lists every flow, the service it goes to and when it was allowed.
- **Local mode** sends nothing to any cloud service, whatever was chosen.

Considered: a dialog per flow and service (the earlier rule), rejected after persona testing found two or three dialogs in the first minute; one dialog per provider at the first send, rejected because the User has already chosen the provider a moment before and the dialog only repeats it.

## Tagging and sorting new Documents by themselves (#2308, #2623, #2982)

**The switch** is "Sort and tag new Documents as they arrive", under the Organize and Tags row in Settings › AI. While it is off, the line beside it says what each new Document would send and to which service: its name and type and an excerpt of its start (about 1,500 tokens), with the Tags' and Folders' names and descriptions, in Settings › Privacy's words. The line says that a Linked folder's new Documents go too, and that Documents already in the Library go only when the User runs Organize. In Local mode it says that nothing goes to a cloud model. Turning the switch on is the consent for the services it sends to then, recorded with its time. ⌘K's "Turn on tagging new Documents…" opens Settings › AI at the switch.

- **Only two places turn it on:** the switch itself and the sidebar row's Allow (below), each with its line on screen. Any other save can only turn it off, so a window with an older view never turns it back on. Choosing a model, whether the row's or the chat model for Answers, never turns it on. First-run setup turns nothing on. (Choosing a model for Tags in the earlier Settings › Tagging used to turn it on; that page is gone.)
- **It is on for where it sends.** On for a model on this computer, or for one service, isn't on for another: when where it sends changes, it reads off until the User turns it on there.
- **Only what is new goes by itself, per service.** Automatic tagging and Organize send a Document to a service by themselves only if tagging was turned on for that service itself, and IncarnaMind saw the Document arrive new after that, or the User's own Organize or re-tag already sent it to that same service. Arriving new means the User added it, or linked its folder then, or the folder's watcher reported it after the folder's first scan; a cloud drive's placeholder that downloads later was there before. A file's own times count for nothing. Both senders check this on the service the request actually resolved to, just before they send. Organize is checked on its own model's service; a scan's page images, which may go to the image model's service instead, pass a separate gate: the scan-images consent the User gives for that service.
- **What the User asks for goes.** Re-tag all is the User's own request for every Document in the places where tagging is on and not stopped, those held since before the turn-on included; while tagging reads off for where it sends, it sends nothing and leaves every Document as it was, and the switch's line asks for the turn-on. Re-tagging chosen Documents, or one Folder, is the User's own request for them.
- **Everything else waits, "off",** for the User to run Organize or a re-tag: an edit, a save by rename, a copy keeping its date, a file found by a later scan (a resume, a restart), one restored from Recently deleted, or one read again.
- **A switch saved before the per-service list reads off for a service outside this computer.** Such a profile has no record of which services the User turned it on for, and nothing stored can tell a turn-on from a consent given elsewhere (to Organize, on the Privacy page, by saving TypeSafe Jev's key). So the older switch reads off until the User turns it on once. A model on this computer keeps its switch, since nothing leaves the computer. No migration or default turns it on, and a save that shows the switch off keeps it off (#2623).

## Dropped Documents ask on their own row (#2308, #2982)

Scans the User dropped were left in no Folder, with nothing saying why. With a cloud model, sorting new Documents by itself is off until it is turned on for that service, so the Documents waiting say so in the sidebar, where the User sees the Library's work, and the User can allow it there.

- **Nothing goes before the press.** Without the switch on for the service Organize sends to, a dropped Document stays in no Folder and nothing of it is sent. Its first pages are still read first, on this computer either way.
- **The press is the consent, for that service only.** The sidebar's footer says "4 to organize · Allow {service}", its popover says what is sent before the press ("…sends each Document’s name, kind and page count, the start of its text and its slide titles or sheet names, with your Folders’ names and descriptions and any matching Tags’, to {service}, for these and for Documents you add later"; page images aren’t named there, since the press doesn’t allow them), and the button names the service. Pressing it records the consent through `src/core/consent.ts` and turns the switch on for that service, with its time.
- **The Documents waiting are read at the press,** as the User's own Organize: every Document in no Folder held back this way, older ones included, as the row's count says. What the run proposes opens for the User to confirm; nothing moves at the press. The request is kept, so a quit before the run ends doesn't lose it. From then on, new Documents are read by themselves.
- **The row asks only for one service.** When turning sorting on would turn it on for another service too (tagging's, such as a saved Jev key), no row asks, and nothing goes: the User turns it on in Settings.
- **Turning the switch off withdraws it,** for every service. Nothing more goes by itself, and Documents that wait show the row again. Another cloud service asks again on its own row. A model on this computer is unchanged.
- **Walls and Local mode still hold.** A Document filed inside a Folder that keeps its work inside it never goes to a cloud service by itself (ADR-0012), and in Local mode the row doesn't show and nothing goes.
- **What arrives in Local mode stays (#2982).** A Document, or a Linked folder with the files of its first scan, that arrives while Local mode is on never goes to a cloud service by itself, then or after Local mode ends. It waits, "off", for the User's own Organize or re-tag, as one held since before a turn-on does. The switch stays as the User left it: what arrived before Local mode began keeps its turn, and what arrives after it ends goes. A turn-on made in Local mode names no service and records no consent. A model chosen there for Organize and Tags records none either, and its first use afterwards asks.

## What the switch lets go, and what waits (#1569, #2339)

Nothing the AI sorts or tags is kept until the User confirms it (ADR-0012). The switch decides only what may leave the computer by itself: with it on for a service, each new Document is read by that service as it arrives, under every rule above. The run files and tags nothing: what it proposes waits in Suggestions, with every other run's, until the User confirms it. A count on the Library's sidebar row says proposals wait.

**What one Organize request sends:** the Document's name and type ("PDF, 46 pages"), the start of its text (its first 6 Passages, cut at about 1,500 tokens), a deck's slide titles or a workbook's sheet names (up to 16, 60 characters each), every Folder's name and description except those the User turned down for it, the name and description of the Tags in the Document's script, and fixed instructions. A scan with no text adds up to 3 page images, only where that flow is allowed. When the only Tag given is an Invoice Tag the text doesn't bear out, a second request asks again without it. No path, size, date or language is sent.

## Other choices in Settings › AI (#2835)

- **A reranking service the User's account already reaches** (Cohere on its account's key) asks before it is used: choosing it in Best results first shows what each search sends and to whom, and only Use this records the consent. While it is chosen, the row says where it sends. A service set up with a key of its own says so in its key form.
- **A company's last key going** sends Document search and Best results first on that company's account back to the built-in models, as sorting already goes back to Automatic (#1907), so a key added later starts nothing on the old consent.

## A decision model reads a check's sentences first (#3118)

Check this Note can have a decision model read each sentence before the User's AI model does. That is the `decision-checks` flow, to the decision model's host. It sorts the Note's sentences first (#3334): each goes alone, with nothing else, to decide whether it needs a check. Every later request holds one sentence that does and its paragraph, with Passages of the User's Documents or parts of them, each under its Document's name and page. The requests such a sentence can cause:

1. The sentence with its Passages: up to 30 the check's search finds, and every Passage the sentence cites.
2. Before a verdict stands, the sentence with the verdict's Passage alone; once more with the same Passage where it writes one of the sentence's numbers another way.
3. The sentence with each sentence of that Passage, to find the line a quote would be.
4. The sentence with that one line alone, under its Document's name.
5. Where no Passage is about the sentence, the sentence with the five nearest Passages joined as one.

Nothing else goes: not another Note, a Folder's or Tag's name, an id or a file path. Since the sort, every sentence of the checked Note reaches the host, as the line the User turns it on by says ("each sentence of a note you check").

- **Chosen.** The User turns it on in Settings › AI, on the row whose line says what goes and to which service. Turning it on there is the consent, recorded in Settings › Privacy, and it then reads every check, also one whose AI model runs on another service. A key to the host saved for something else turns nothing on.
- **By default, only where the check already goes.** For a User who hasn't said, a measured decision model reads only when the User's own AI model for checks runs on the same service as that model's host, and then only the checks that go to that service. The User asked for the check, and it already sends the Note's text and the Passages found for it to that service: no new kind of data goes, and to no new service. So the User's choice of that service for their checks covers it, and there is no dialog. Settings and Settings › Privacy show it by that same rule, so neither says off while a check is read. A Note checked with a model on another service is not read by default, whichever of the two services the decision model is on.
- **Whose model it is.** A service can pass a request on to the company whose model it is: Decider v1.2 is Perplexity's, reached through OpenRouter. Where that company is not the service, the Settings row's tip and the flow's line in Settings › Privacy name it.
- **Said where it lives.** The Settings row is a switch, shown on, with a line naming the model and a line saying which checks it reads and what they send to which service. It shows on before the User's first check too, which asks about checks itself; nothing is read until they allow that. A first reading's own explanation names the model; its service is named in Settings and in Settings › Privacy. Settings › Privacy lists the flow from the same rule once checks go to that service, before its first use too: on with the User's checks, never as something they allowed by an act. The first check that reads records the date, which Privacy then shows.
- **Ended** by turning it off, in Settings or in Settings › Privacy, before any check or after: off forgets the record, and no later check turns it on again. Undo in Settings › Privacy brings it back as it was. Removing the host's key ends it too, and forgets a model the User chose. Local mode sends nothing.
- **The record serves this flow only.** It is kept for `decision-checks` to that one service, and nothing reads it as consent to another flow or another kind of data.
- **Never asked, never a problem.** A check never asks for this flow. A request the host refuses, or doesn't answer within 5 s (the slowest of 13,179 measured answers took 3.6 s), ends that check's readings and is logged: the AI model checks those sentences as it would with no decision model.
- **One value ships it.** Reading by default is on by the gate in `eval/evidence/3118-decision-first`: its bars and, where one was not met, the owner's decision written there with the numbers. With the value off, the model reads only where the User chose it.
