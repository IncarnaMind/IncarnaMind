# Deep analysis: more Python in the Analysis sandbox first, then code runs in the OS sandbox

Analysts ask for more than totals and group-bys: regressions, tests, clustering, forecasts and plots. They want the assistant to work as an agent harness does: write code, run it, read what it printed, and run again. An Analysis (ADR-0023) runs Python in Pyodide with numpy and pandas, in a hidden sandboxed window with no network and no files, on Inputs cited from Documents, on every system. A Skill script runs through the "os" Executor (#65): Seatbelt on macOS and bubblewrap on Linux, through `@anthropic-ai/sandbox-runtime`, with no network; Windows has no OS sandbox, so Skill scripts there ask every time. A User with an agent harness of their own can already bring it (ADR-0013's addendum; #353). This record is about IncarnaMind's own assistant, which most Users will use.

The spike on the branch `spike/run-code-sandbox` measured three ways to give the assistant more: Pyodide's own builds of scipy, statsmodels, scikit-learn and matplotlib; a `run_code` Tool that runs bash or Python in the OS sandbox on copies of Documents; and, for that Tool's Python, a bundled CPython or the User's own `python3`. Its prototype, tests and probes are on that branch (`src/core/runCode/`, `tests/main/runCode*.test.ts`, `spike/run-code/`).

What #2346 built is decision 1, and decision 3 as it applies to Analyses. #2351 builds decisions 2, 3 for `run_code`, 4 and 6 on macOS and Linux. Windows (decision 5) stays proposed.

## Decision

In this order:

1. **Analyses gain scipy, statsmodels, scikit-learn and matplotlib** (#2346, accepted).
   - They are Pyodide's own wheels, fetched at build time and checked against the SHA-256 its lock file records, as numpy and pandas are (`scripts/pythonRuntime.ts`). They run under ADR-0023's Content-Security-Policy as it is, and ADR-0023's probes still fail with every package loaded (`e2e/analysis.spec.ts`).
   - **A job loads only the packages its code uses.** The spare interpreter keeps only numpy and pandas, so an Analysis that uses only pandas starts as fast as before. Before the code runs, the helper reads its imports, and the two places pandas imports one itself: plotting (`.plot`, `.hist`, `.boxplot`) loads matplotlib, and a Spearman or Kendall correlation loads scipy. Loading them is bounded by the start limit, and the job's time limit runs from when they are loaded. A package a library imports that the code didn't name ends the run with an error that says to import it at the top.
   - **matplotlib draws with its Agg backend into PNGs.** Every figure pyplot makes while the code runs comes back as a picture, closed or saved or not, at twice its size in points, no longer than 1,600 pixels and no larger than 1.5 MB, as a Note keeps a pasted picture (#1937). A figure wider than 5 inches is drawn 5 inches wide, so its text stays legible where the assistant panel shows it about 400 px wide. Until the Analysis block (#448), the Answer shows it where it writes `[=picture n]` on a line of its own, as a picture Block; a chart or picture the reply never places is added at the Answer's end. `chart()` stays the way to draw a bar, line, pie or scatter chart the app draws and a Note can restyle, and the Answer's instructions say to use it where it can.
   - **Chinese in a plot.** matplotlib's own fonts (DejaVu, STIX) have no Chinese. Noto Sans SC 2.004 (SIL Open Font License 1.1), cut to GB2312's 6,763 characters with its punctuation, ASCII and Latin-1 (`scripts/plotFont.py`), ships beside the packages. A job that draws adds it after matplotlib's own family, so Latin text looks as before and each character DejaVu lacks is drawn with it. The renderer never loads it. A plot with a character neither has (Japanese, Korean, a Chinese character outside GB2312) would show boxes, so it is left out, and the model reads why and to use `chart()` or other labels.
   - Nothing else changes: the same Inputs cited to their cells, the same `result()`, no clock, and the versions of every bundled package recorded with each run.
2. **A `run_code` Tool runs bash, or Python, in the OS sandbox, on macOS and Linux.**
   - **Inputs.** It names the Documents it reads by the ids of Passages the model was given. Each is copied (a copy-on-write clone where the disk has them) into an `inputs` folder the code can read but not write. The copy must have the SHA-256 the index recorded as the Document's content hash. A file that changed since is refused, and the model is told to read it again.
   - **Where it writes.** The code runs in a working folder of its own, which is also its TMPDIR and the only folder it may write. It has no network.
   - **Limits:** a time limit (120 s); 64 KiB of each output stream kept; the largest file it may write (100 MB); how many processes it may start, counted over those the User's account already runs (64); its memory (2 GB, its processes together); the size of its folder (200 MB).
   - **What comes back:** what it leaves in `out/`, up to 20 files of 5 MB each, read once it has ended, after its working folder is moved where the sandbox can't write, and never through a link: an `out/` or a working folder it swapped for one comes back as nothing. Nothing it writes reaches a Linked folder or a Note by itself. The assistant adds a file or a figure the usual ways.
   - **What the sandbox denies.**
     - Reading: the home and data folders, every account's home (`/Users`; `/home`, `/root`), the shared temporary folder (`os.tmpdir()`, which the spike found readable), removable and network volumes (`/Volumes` on macOS; `/media`, `/mnt` and `/run/media` on Linux), and on Linux `/run/user/<uid>`. Each run's own folders are allowed again inside them. What stays readable is the system's own files.
     - On macOS, also LaunchServices, the Keychain's server and distributed notifications.
     - The network: DNS, the internet and loopback.
     - The login environment: code gets only its `PATH`, `LANG`, `LC_*` and `TZ`.
     - On Linux, bubblewrap puts an empty folder over each denied one (its masks hold 1 MB), so a file there isn't found rather than refused. What is written in `/tmp` goes to the run's own empty folder, never the real one. The working folder is mounted, so it can't be removed or swapped for a link.
   - **bash** is the system's own `/bin/bash`, with the tools the system has.
   - **Python is IncarnaMind's own** (amended 2026-11-01, #2351, replacing "the User's own `python3`"). The User's own `python3` is never used.
     - **What it is.** A pinned CPython from python-build-standalone, with a fixed set of wheels locked by their SHA-256: numpy, pandas, scipy, statsmodels, scikit-learn, matplotlib, pillow and openpyxl, and what they depend on. `scripts/pythonNative.ts` builds it on each platform's runner from one lock for every platform (`scripts/pythonNative/lock.txt`), checks every download against its SHA-256 and installs offline, so nothing is resolved from an index. The wheels are chosen for the oldest systems the app runs on: macOS 12 on Apple silicon, and glibc 2.28 on Linux x86-64 (`manylinux_2_28`).
     - **What a run records:** CPython's version, each package's version and the runtime's SHA-256, beside the helper's, as an Analysis in Pyodide records Pyodide's. The runtime is pinned, so a figure from code without `of` can be run again to the same result.
     - **Downloaded on first use, as the speech model is,** so no installer grows. The release workflow builds it on each platform's runner and uploads it to the same GitHub Release as the app, as `python-runtime-<platform>.tar.zst`. Its size and SHA-256 are written into the app at build time (`python-native/runtime.json` in the app's resources), so the app only accepts the file built with it. A version whose runtime is byte-for-byte the same as the last one's keeps the copy already downloaded.
     - **When.** The first `run_code` call that runs Python, never at launch and never in the background. That call's step says what is downloading, how big it is and how far it has got ("Downloading Python: 31 of 117 MB", then "Getting Python ready…" while it is unpacked and first imported). Stopping the Answer stops it once no other call waits on it; what was downloaded is kept, and the next call resumes it. bash needs no download.
     - **Checked and stored like a model.** It downloads to `runtimes/` in the app's data folder, resumably, and is kept only when its size and SHA-256 are the ones built into the app (`embedding/download.ts`). It is unpacked there, never in the User's home, and imports its packages once, in the OS sandbox, before its first run. A runtime that fails its check is deleted.
     - **When it can't come** (offline, a failed download, a file that doesn't match): the step says so in plain words, the model is told, and it runs the Analysis in Pyodide instead (decision 1). The next call that needs Python tries again.
     - **No consent card (ADR-0022).** The download sends nothing of the User's: one GET for a file IncarnaMind published, from the host its updates come from, carrying no Document, Question or setting, as the model downloads do. The Privacy page lists it with the other traffic that carries no User content.
     - **Signing.** The runtime is outside the app bundle, so the app's signature and notarization don't cover it, and its Mach-O files are not signed one by one. On Apple silicon each carries the ad-hoc signature macOS requires to load it (the linker's own, or one made when its wheel was repaired). A file IncarnaMind writes itself carries no quarantine attribute, so Gatekeeper doesn't assess it. Importing every package once before the first run takes macOS's first-load check while the step says Python is getting ready, not in the User's first analysis.
3. **A figure from code keeps the trust story of ADR-0021.** The model never types a number. Code gives a figure the app can check with `figure(name, column, how, label, unit)`, and any other number with `result(name, value, label, unit)`. Analyses (accepted, #2346) and `run_code` (#2351) share one contract: `run_code`'s helper takes the same `figure()`, and the check covers both.
   - **Where the column comes from.** An Input's rows keep their row number in the sheet as the DataFrame's index, named `row`, never among the data a sum or a model would take in, and the DataFrame knows which Input it is. In `run_code`, `read_table(name, sheet)` gives such a DataFrame, the headings being row 1: IncarnaMind reads the copy itself, with the reader its index uses, so the cells are the ones Citations are checked against, up to 200,000 rows and 2,000,000 cells of a Document (past the index's 20,000 rows). `figure()` takes one column of an Input's rows, after any filtering. A merge, a group-by, a concat or `reset_index()` drops the row numbers, and `figure()` then refuses the column rather than name the wrong rows.
   - **What a figure records.** `how` is sum, mean, min, max or count. The helper works the value out itself, so the value and its cells can't disagree. It records the Input and its Document version, the column's heading, the rows (as runs of consecutive rows, at most 2,000 runs; a figure over more is refused, and the model is told to give it with `result()`) and `how`.
   - **The check.** IncarnaMind reads the cells itself (for an Analysis, the cells it read from the Document version and sent to the sandbox), works the figure out again with its own arithmetic, the way the helper reads a column (a mostly-numbers column skips its text cells), and compares the two to Excel's 15 digits. Only a match gets a marker: its card says what the figure is of, in which rows, and that IncarnaMind worked it out again from those cells when the code ran; in `run_code` it reads "Inputs found · recalculated", its Inputs cited as a rows Citation. A mismatch, or a reference it can't follow, gets no marker and is never shown as a figure; the model reads why, and the number the cells come to. The outcome is kept with the run (`recalculations`). The check needs no sandbox, so it can run again on Recalculate as `calculate`'s does. #2351 checks when the code runs, as Analyses do; working a `figure()` figure out again on Recalculate comes with `run_code`'s figures and the sentence's check of Analysis figures (#2351).
   - **Figures without a way to work them out.** A regression coefficient, a p-value or a forecast is an Analysis figure, kept with its code, its Inputs' Document versions and hashes, and the runtime's versions, and shown as calculated by code and not recalculated. `result(..., of=rows)` names the rows and columns of an Input it was worked out from, such as those a model was fitted on, and its card shows them. Both runtimes are pinned, so such a figure can be run again to the same result (amended 2026-11-01).
   - **Only as markers.** Code's figures reach an Answer only as markers (`[=n]`). A number the reply writes without a marker is caught as ADR-0021 already catches one (#1796), unless it is a number its code printed (below).
   - **A sentence's check** (amended 2026-11-04, #2378, and 2026-11-06, #2544). An Analysis figure in a sentence is judged by its run, never against the Documents' text, which never holds it.
     - Its number is IncarnaMind's: worked out again to the same number, while the Documents it read are as they were.
     - Whether the sentence names it is the claim judge's call. The judge reads the figure's label, its rule and rows, and the run's code, and says the sentence names that figure, names another, or can't tell.
     - Code never upgrades a figure to Supported. It is Supported only when the judge says the sentence names it and a no-model filter, which can only take that away, passes (`src/core/answers/checks/analysisNaming.ts`). The filter reads a closed set of words: the sentence's words around the figure, up to the figures beside it, must hold every word of its label and nothing else but the Analysis's own words for its input, columns and unit, its words for its own way of working it out, and words that only link a figure to its name. A word only another figure is named by, a sign or symbol those words don't hold (a dash or the accounts' brackets that touch the figure among them), a target ("has to reach"), a total made one item's ("a North order's total"), or a scale, currency or percent said around it (in its paragraph, the heading above, the lines above it in its section or the opening lines of the sections it is under) that the figure's shown number, its unit or the Analysis's own words don't give it, each leaves it unchecked. A table cell's headings are read the same way.
     - A sentence the judge reads as naming another figure is Unsupported ("The sentence doesn’t say this figure is {label}"); anything else is Not checked ("The sentence doesn’t clearly say this figure is {label}"). A figure not worked out again reads Not checked ("From the Analysis · not recalculated"), and one whose record is gone reads Not checked ("The Analysis it came from is no longer available").
     - Until a check reads its sentence, and once the sentence's words change, the figure has no verdict of its own. Every other assertion in the sentence is checked as usual. A table's column earns the note's ✓ only under its input column's own name.
   - **Tables in PDF, Word and PowerPoint Documents** (amended 2026-11-02, #448).
     - The index keeps each table of figures it reads with its Unit (`UnitLabel.tables`, processing version 23): a PDF page's from where its words sit, with the reader the Verify tables use (`src/core/documents/tables.ts`); a scanned page's from its recognized lines; a Word file's or a deck's from the cells the file gives, a Word cell merged across columns or down rows keeping the grid's columns.
     - A table that runs over pages, headed again on each or not at all, with only running lines or a "continued" line between, is one table.
     - An Analysis names one by a Passage and, where the Passage shows several, its number, and reads it as a sheet's range: its headings row 1, its rows numbered on across pages, each row cited to the Unit it is on.
     - Each cell is found again in its Unit's stored text before it is read. One that isn't there, or that a scan's recognizer was unsure of, stays text, so a figure over it is never worked out again. A footnote mark after a figure ("17,347.75²") is left out of its value, never read as a digit.
     - A table read from a scan gives no recalculated figure: its numbers are what a recognizer read, and working them out again would only agree with themselves.
     - No second parser: the index's own reading is what Citations are checked against.
   - **A number its code printed** (amended 2026-11-03, #2351). Models copy what code prints into their replies, and an instruction not to didn't stop Claude Haiku 5.5 on held-out requests, so the Answer handles it structurally.
     - A number the reply types that equals one an Analysis of the Answer printed, or wrote to a text file in `out/`, also before the run failed, becomes that figure: calculated by code and not checked, as a `result()` figure without a way to work it out is, kept with its run, its printed line as its label, in the Answer and in what it writes into a Note (content schema 49, as a bash run's record is new there).
     - It matches as the figure check matches a sentence's number to a calculated figure (`agreesAtShownPrecision`): the same unit, scale, percent and sign as `src/shared/figures.ts` reads them, at the reply's own rounding. So "12.3" is the 12.345 printed, and "45.2%" isn't the 0.452 printed, a bare number.
     - A whole number written plainly, or as approximate with one or two significant digits ("about 40", "below 100"), matches only the same number printed: rounded to a whole, every count and id in a reply would match some printed decimal.
     - Where printed numbers of different values match, one printed exactly as written decides, else none. A number its sentence's Citation quotes stays the Citation's.
     - A printed copy of a `figure()` figure whose cells came to another number ("differs"), in any of the Answer's runs and at the reply's rounding, is refused, never marked. A printed copy of one IncarnaMind couldn't work out again is marked "calculated by code, not checked": the code did work it out, and nothing checked it. Only `figure()` is worked out again: a printed number, bash's included, never reads as recalculated.
     - Never matched: a number cut off where a printed stream or an `out/` file's preview ends, which was never printed, and a printed table's index (0, 1, 2…). A table's headings and row labels stay text, as the checks read a table, and a number whose characters would read differently as a figure stays as typed.
     - A printed figure's marker is numbered above every figure marker the reply wrote, so a marker it wrote with no figure never shows a printed number. A number that matches nothing printed and nothing cited goes on to the net above (#1796).
4. **What asks.** The rules are approvals by Effect, as ADR-0013 sets out:
   - **Runs without asking.** `run_code` at level "os" is "sandboxed code", ADR-0023's Effect scope, which now covers both sandboxes. It reads only copies of Documents the Run may already read, writes only its own folder, and can't send anything. So it runs without asking, also after the Run has read third-party text (#78).
   - **Asks every time, Allow or Don't allow, never "always":** a call that names a folder outside the Library to read (a granted folder). #2351 builds none: `run_code` reads only Documents named by their Passages, so nothing it does asks.
   - **Not offered:** network for code, writing outside its own folder, and `run_code` wherever the OS sandbox can't start. ADR-0013's rule for a Shell is that it fails closed and never gets Tool-level "always", and bash on the User's computer is a Shell.
5. **Windows.**
   - **Until Windows has an "os" level,** `run_code` isn't offered there. Analyses run there now, in Chromium's sandbox.
   - **That level will be an AppContainer with no capabilities inside a Job Object,** started by a small signed helper. It needs no administrator rights or UAC prompt, and runs on Windows 10 22H2 and Windows 11.
   - **What it gives:** no network, loopback and DNS included; writes only to the folders granted to its container; limits on processes, memory and CPU time; kill-on-close for every process it started.
   - **Its limits:** system folders stay readable, and writing to `NUL` fails.
   - **MXC replaces it** once most Users run Windows 11 24H2 build 26100.9278 or later. MXC is Microsoft's container SDK, which Codex prefers.
6. **Linux.** The OS sandbox needs bubblewrap, socat and ripgrep, and unprivileged user namespaces, which Ubuntu 24.04 restricts through AppArmor. Where the sandbox can't start, `run_code` isn't offered, and the User reads why and how to fix it, as Analyses already say when Chromium's sandbox is off: Settings › Skills says the sandbox can't start, names the packages to install, and links to `docs/linux-sandbox.md`, which says how to allow user namespaces. The assistant then analyses in Pyodide alone.

## Licences

**python-build-standalone's MPL-2.0 is allowed, shipped unmodified,** approved by the project owner on 2026-11-01 (`AGENTS.md` rule 8 names it beside Pyodide).

- Its `install_only` archives carry only CPython's own `LICENSE.txt`. The licence texts of what CPython is built with (OpenSSL, SQLite, libffi, mpdecimal, expat, zlib and zlib-ng, bzip2, liblzma, zstd, libedit, ncurses, Tcl/Tk and Tix, libuuid, libX11, libXau, libxcb and Berkeley DB) are in the same release's full archive, under `python/licenses/`. The build copies them all, with the wheels' own licence files, into the runtime's `LICENSES/` folder, and checks that every library the build includes has its text.
- **One module is left out** (the project owner agreed, 2026-11-01). On Linux, the `_dbm` module statically links Berkeley DB under the Sleepycat licence, which asks that the source of software using it be offered: not a licence rule 8 allows. No analysis needs `dbm.ndbm` (`dbm` falls back to SQLite), so `lib-dynload/_dbm*.so` and its licence text are left out of the Linux runtime. On macOS `_dbm` links the system's own ndbm, and stays. No other file of python-build-standalone's is changed.
- **The wheels' own libraries are allowed too** (the project owner, 2026-11-01; `AGENTS.md` rule 8). scipy's wheels on every platform, numpy's on Linux and on macOS 12, and scikit-learn's on Linux bundle the GCC runtime (libgfortran, libgcc_s, libgomp: GPL-3.0-or-later with the GCC Runtime Library Exception 3.1) and libquadmath (LGPL-2.1-or-later), each as a library of its own that the package links to as it runs. No scipy wheel exists without them, and every numpy and scipy install ships them; Pyodide's own builds avoid them, which is why decision 1 needed no exception. They ship unmodified, as their wheels have them, each its own dynamically linked library, with their licence texts and a link to GCC's source. The build names them, and the packages each may come in (`COPYLEFT_ALLOWED` in `scripts/pythonNative.ts`), and fails when one turns up elsewhere. A change to the lock is a new runtime, read for what its wheels bundle, as an upgrade of Pyodide's wheels is (#2346).

**What decision 1 adds to the Analyses' notices** (#2346). `resources/notices/python.txt` gains, with their licence texts from the wheels: scipy, statsmodels, scikit-learn, joblib, threadpoolctl, contourpy, kiwisolver and cycler (BSD-3-Clause); patsy (BSD-2-Clause); packaging (Apache-2.0 or BSD-2-Clause); fonttools and pyparsing (MIT); pillow (MIT-CMU); and matplotlib (the Matplotlib License, PSF-based, with the DejaVu and STIX fonts' notices). It points to the licence files scipy, statsmodels and scikit-learn carry in their wheels for the code they bundle. It credits the native libraries compiled into the wheels' modules, with their texts:

## Measured

On the Apple M2 Max used for ADR-0023, macOS 26.5, with other work loading the machine, so the times are noisy. The full tables are in this record's earlier versions, the probes' results on the spike branch (`spike/run-code/`), and the held-out requests in `eval/runCode/cases.ts`.

- **More Python in Pyodide** (#2346): a pandas job is as fast as before; a job that imports one of the four took 1.8 s (matplotlib) to 4.1 s (scikit-learn), and 6.8 s with all four. No load fetched anything but the bundled files. The macOS dmg grew 37.5 MB (229.9 to 267.4 MB).
- **Why `figure()` and not `result(of=, how=)`:** with Claude Haiku 5.5 on held-out questions, `figure()` had 6 of 6 figures recalculated and 2 of 10 calls fail; `result(of=, how=)` had 3 of 4, and over half its calls fail. Asking the model again for the rows of figures that named none once turned a right share into a wrong one, so it isn't asked.
- **The OS sandbox** adds about 40–50 ms to a start: in it, `python3 -c pass` took 58 ms and `import pandas` 372 ms. `run_code` on a 50,000-row CSV with three `figure()` figures, a table and a chart took 1.9 s.
- **Printed numbers** (#2351, ten held-out requests, Haiku 5.5): on `main`, 7 of 10 replies typed numbers their code printed without a marker (26 in all); with the marking, none did, and all 23 that became figures were genuine.
- **IncarnaMind's own Python** (darwin-arm64): a 116.9 MB archive, 527.8 MB unpacked, the same bytes from two builds. Its first import in the OS sandbox took 52–66 s (macOS checking each native library once per copy), then 2–3 s.
- **Containment** (`tests/main/runCode.test.ts`, on macOS and CI's Ubuntu 24.04): every read, write and connection decision 2 denies was refused, in bash and in Python. Windows isn't measured.

## Considered options

- **Pyodide alone.** Kept as the first step, but not enough alone: no shell, a 32-bit WebAssembly memory (a `MemoryError` near 4 GB), one thread, and Inputs limited to the rows the index keeps.
- **A CPython bundled in the installer** (python-build-standalone, wheels installed by uv). Chosen on 2026-11-01 for native speed, every package and figures that can be run again, but downloaded on first use. Bundled, it would add 98–140 MB to each installer and need 336 native libraries signed one by one with the hardened runtime on macOS. On Windows, SignPath Foundation's terms allow signing only what the project builds, so `python.exe` and every `.pyd` would ship unsigned, which Smart App Control blocks where it enforces: for decision 5.
- **The User's own `python3`.** Chosen first, rejected on 2026-11-01: on a Mac out of the box it is Xcode's Python 3.9.6, without pandas, so most Users would have had bash only; and its versions vary, so its figures without `of` couldn't be run again.
- **No sandbox, asking before every run** (the classic Open Interpreter and Cline). Rejected: ADR-0013's rule for a Shell; Anthropic found users approve about 93% of permission prompts; and a prompt can't bound what an approved program does.
- **A cloud interpreter** (OpenAI's Code Interpreter; the Claude API's code execution tool). Rejected: the User's Documents would go to a service the User didn't choose (ADR-0022), it wouldn't work offline, and Local mode couldn't use it. Its results contract was copied: an output folder whose files come back.
- **Windows:**
  - A sandbox account with firewall filters (Codex's elevated mode; sandbox-runtime's Windows alpha): needs one UAC prompt.
  - Windows Sandbox: needs an administrator, isn't on Home, has the network on by default, and gives no output back.
  - WSL2 (Claude Code, Cursor, Zed): needs an administrator to install, and runs Linux, not the User's Windows Python.
  - A restricted token at low integrity (Gemini CLI): doesn't confine reads or the network.
  - MXC: needs Windows 11 24H2 build 26100.9278 or later, is a 108 MB package, has no resource limits, and reached 1.0 on 2026-10-07. It replaces the AppContainer helper later.

## Consequences

Of what #2346 built:

- **Installer size.** It grows by about 37.5 MB on every system, so Python's files and the font total about 50 MB compressed. `scripts/check-package.mjs` gives each installer its own limit: its size in 0.1.0-alpha.5, these 37.5 MB, and about 5 MB (AppImage 275, dmg 270, zip 263, exe 242, deb 226 MB).
- **A job that uses them waits for them.** A job that imports one of the four takes 2–7 s more on this Mac than a pandas job, most of it importing the package; more on a slower computer.
- **A Chinese font ships.** GB2312's second level, which holds characters common in people's and companies' names, costs about 0.5 MB more than its first level alone; the whole set is worth it. Japanese, Korean and rarer Chinese characters still leave a plot out.
- **Content schema 46.** A Note keeps an Analysis figure's rows with its kept value, so an older version opens a Note written since read-only.
- **The packaged app's engine check** runs a regression, a forecast, a clustering and a plot in the Analyses window, on macOS, Windows and Linux.

Of the rest, once built (#2351):

- **Offered where it was measured.** `run_code` is the model's fact `codeTool`, as `calculates` is. It shipped off for every model until a number its code prints was marked in the Answer (Haiku 5.5 wrote such numbers into every `run_code` reply). It is now on for Claude Haiku 5.5 and Sonnet 5.5, and off for every other model until a run measures it. The Claude account's sign-in serves the same two models and reads their facts.
- **The Executor.**
  - `ExecRequest` gains `limits`. The "os" confinement sets `ulimit -f` and `ulimit -u`; the process limit counts per account on macOS and Linux, so it is set over the account's count when the run starts. On Windows the Job Object will hold these limits.
  - **Measuring** (`src/main/programMeter.ts` says how). Memory and the folder's size, including files a run's processes hold open after unlinking them, are measured every 250 ms, and a run over a limit is stopped with every process it started. A run whose disk can't be measured is stopped too, a legitimate one included: at once when a read of its open files fails (as for a program that makes itself non-dumpable), and once its disk has stayed unknown for more than ten seconds in a row (a slow read or, on Linux, more than 8,192 descriptors or 32 MiB of maps). Reads are paced so a run that makes them heavy holds the app to at most a quarter of its time and a quarter of a core. So a run's writes can go unseen for up to about ten seconds; the time, memory and folder limits keep running meanwhile. The OS sandbox doesn't start on a Linux whose processes have no `NSpid`.
  - **Leftover processes** (`src/main/runLeftovers.ts`). What a program left running, in its process group or outside it (a daemon, a worker pool, a session of its own), ends with it: at its end, on a timeout and on Stop. On macOS a process is the run's only by its Seatbelt profile, never by anything the code controls; an earlier sweep that went by the folder a process may write stopped another program's sandboxed commands. On Linux bubblewrap's PID namespace ends them. A crash's leftovers are swept at the next start, and new runs are refused while a process of an earlier one can't be stopped.
  - In macOS's sandbox, loky can't read the system's semaphore limit, so scikit-learn's process pools fail. `run_code` sets `JOBLIB_MULTIPROCESSING=0`, so n_jobs runs in threads and no pool outlives the program.
- **IncarnaMind's own Python, in the sandbox.**
  - `getcwd()` fails in macOS's sandbox, which denies the folders above the working folder, so `os.getcwd()`, `os.path.abspath()` and `Path.resolve()` of a relative path raise `PermissionError` and matplotlib can't start. Allowing those folders would show other apps' temporary files' names, so the runner tells Python its folder (`os.getcwd`, kept in step with `os.chdir`), and bash gets `PWD`. A program that asks the system itself (`/bin/pwd -P`) still can't.
  - The runtime's folder can't be written while code runs, so the build compiles the standard library (`unchecked-hash`, 3 MB more), and matplotlib's font cache is built beside the runtime and copied into each run (built in each run, it took about 8 s a plot).
- **The OS sandbox** also denies the shared temporary folder and removable and network volumes, for Skill scripts too.
- **sandbox-runtime** moves from 0.0.79 to 0.0.81 in the same change. On Linux, 0.0.80 stops commands from creating namespaces and lets `denyWrite` win over `allowWrite`.
- **Effect scope "sandbox"** names sandboxed code in either sandbox. Its approvals don't change.
- **A word for the interface.** A run of `run_code` is an Analysis (数据分析) in the interface, as one in Pyodide is: which sandbox ran it makes no difference to the User (#2351). CONTEXT.md's Analysis runs "in a sandbox, with no network, reading only the files it was given". "Run code" appears only in the Details view, beside the code.
- **Linux in CI.** The jobs install bubblewrap, socat and ripgrep and lift Ubuntu's AppArmor restriction on user namespaces for the test step. Without that, the OS sandbox's tests and `run_code`'s are skipped; the real-runtime job fails instead when the sandbox can't start.
- **Windows.** The AppContainer helper is a new native component to build, sign with the app's certificate, and test on Windows 10 22H2 and Windows 11 with Smart App Control enforcing.
- **The hosted version** doesn't offer `run_code` until it has a remote sandbox (ADR-0013).
