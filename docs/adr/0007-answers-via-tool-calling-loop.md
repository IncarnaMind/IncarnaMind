# Answers are produced by a tool-calling loop, not a fixed pipeline

## Context

The old backend answered through a fixed pipeline: split the question into sub-questions, pick relevant files, search, then answer. MCP servers and Skills, part of version 1, need a Tool loop anyway, and a loop saves two model calls, because the model itself decides how many searches to run and what to search for.

## Decision

An Answer is generated by letting the chat model call Tools until it is done. The first Tool searches the User's Documents, and the sliding-window grouping of Passages lives inside that Tool. MCP servers and Skills add more Tools. Since ADR-0013 (2026-10-09), Tools come from Tool providers and declare their Effects, an Answer is one kind of Run, and the loop sits behind a `RunEngine` interface.

### The loop's library: AI SDK 7, not pi

The loop is built on AI SDK 7's `ToolLoopAgent`, with the official MCP SDK for Connectors and our own small `SKILL.md` loader (confirmed by the User on 2026-10-07). The bake-off of 2026-10-09, run behind `RunEngine` with a scorecard fixed before any run (speed weighted 15%), scored AI SDK 7 86.3, pi-agent-core with pi-ai 71.1 and pi-coding-agent 68.4 of 100: the same replies and the same safety checks, but pi cost a model bridge, a build change, 77 to 98 more packages, about twice the code and 130 to 620 ms more at app start. The `prototype/*` branches are no longer on `origin` (#2004); the scores stand. The choice stays reversible behind `RunEngine`.

### Searching in the loop

- **No cap of searches** (#946, 2026-10-16). A cap made models write "my search limit ran out" into Answers. A search that comes twice (the same words, whatever their letters or punctuation) is told once to use the Passages the model has or to search for something else; the only bound is the Answer's step budget, ten model calls.
- **Searching again in the Documents' language** (#67, 2026-10-10). When the Question is in another language than the Documents, the search Tool tells the model to search again with the query translated (ADR-0009: search finds Passages best in their own language; cross-lingual Questions were found 1 or 2 times in 10 without that second search, 7 or 8 with it).
- **Retrieving first is off for every model** (#1633, since 2026-11-04). The engine can search the Question's own words before the first call (keyword search's top 20 reranked, 12 Passages), without rewriting or translating it first, and hand them to the loop as its first search, with a note to search again when they don't hold all of the answer; the model then answers and cites in one call (#489's way) or searches on. It applies only to models on the list in `src/core/providers/catalog/answerPaths.ts`, which a model joins or leaves only on paired runs against `eval/speed/gates/retrieve-first.md`, and only on a turn offered no Tool that writes a Mind: searching before the model reads the words is right only for a Question about the Documents.
  - **No model is on the list:** one-call Answers went partial where the loop's own searches find the rest. Claude Haiku 5.5's judged right fell from 60 to 57 of 65 (2 allowed); Claude Sonnet 5.5's every-Citation-found fell from 63 to 59, mostly on quoted words the check misreads (#2504).
  - It would come back with a second search where the first Passages don't cover every part of the Question, on the same gate; Sonnet 5.5 is measured again once #2504 is fixed. A model that retrieves first cites as the write-then-cite list says (#489), never in a way whose own gate it failed.
  - Comparison table cells, a Meeting's notes, a Task's Answer and call help keep the loop by construction; an outside agent's Question keeps it because no list entry names its flow. A check's Run does not: it starts from its sentence's own search, below.
- **A check's Run starts from its sentence's own search** (#3512, 2026-11-21). The check's Run takes the engine's first search, the sentence's own words searched by code in the check's own scope, as its first step, with the note to search again when those Passages don't decide it. It applies to every model, not the list above, because it is measured on the checks' own sets: requests down 34% to 49% and time down 28% to 38% on Claude Haiku 5.5, with the standing set, the planted sets and the dropped-condition set no worse. It does not make the same file's marks steadier: the changes that come from what a check sends went from 55% to 10% of sentence pairs, and what remains is the model's own draw on identical Passages.

### End-of-turn checks

When the model stops, one list of checks reads its reply in a fixed order (`src/core/answers/turnChecks.ts`): a reply that claims a change no call made; one that says its edits fixed a word or a number of things they didn't (`claimedFixes.ts`); one that says a Tool calculated, checked or searched when no call did (`claimedTools.ts`, #1796, for every Answer the User reads, its ask shown as a step); quotes with no Citation; and, when it is built, coverage. Each may ask the model once more with a note, or flag the Answer. They share one small total of asks, inside the step budget; what is left is flagged the same way: the reply kept, with a line under it saying what wasn't done, and Try again.

- **A quick model checks change claims** (#1655, 2026-10-25). After an assistant turn that offered the Minds' Tools, one structured request on the provider's quick-tasks model (the local model in Local mode) reads the reply against the record of the turn's Tools and returns each claimed change, backed or not; an unbacked one gets the re-ask and the line. If the check fails or can't be read, it finds nothing rather than put a false warning under an honest Answer. Wording patterns remain only as a streaming hint until the verdict.
- **Citations for what an Answer quotes without markers** (#760, 2026-10-14). Claude Haiku 5.5 sometimes quotes Passages with no `cite` call, or with markers and no records, and the Answer showed "no sources". So a sentence without a Citation that quotes a Passage word for word, or nearly repeats one of its sentences, gets the Citation the check finds; a marker no record backs, or quoting with no Citation at all, asks the model once; and a marker still unbacked is taken out, so its sentence reads as uncited (`src/core/answers/unmarkedQuotes.ts` has the rules). Tool-call text such as a `<cite>` block never shows: its records count as `cite`'s, and other blocks are dropped (`toolText.ts`). The cost is at most one request, shown as "Checking quotes…" (`citedAfterChecking`). Once Passages were read, the line under an Answer never says "no sources": it says how many it read and how many sentences were cited after checking, or that none could be matched. **Changed 2026-11-19 (#3410):** code no longer gives an uncited sentence a Passage's Citation by its words: on invented near-twins it attached the wrong Passage to 46 of 48 (a swapped party, may for must, a unit, a period, a direction) and to none of the sentences that say the same in other words. A sentence the model doesn't cite has no Citation; the one request for those it left out stays. In the assistant, the Answer's own judgement reads its uncited sentences against the Passages it read, in the same batches as its cited ones: one they don't back is marked, and one a Passage states gets that Passage's Citation, found by the check, only where the model names the words and the Citation check finds them.

## Considered options

- **Keep the fixed pipeline:** two extra model calls, and no room for MCP or Skills.
- **Become a general desktop agent like Tencent's WorkBuddy:** rejected. IncarnaMind stays a documents-first notebook; Tools extend what a Question can draw on and do.
- **pi-coding-agent:** a coding-agent product, not a library. It reads and writes `~/.pi`, discovers its own Skills and `AGENTS.md` files, can't be fully isolated, and keeps Connector tokens in a plain JSON file, which breaks the keychain rule.
- **pi-agent-core with pi-ai:** ESM-only, so it doesn't load in our CommonJS main process; heavy (98 packages, 153 MB, and a second set of provider SDKs); and no saving in code (about 380 lines against 231 for the same tested behaviour).
- **Mastra and the OpenAI Agents SDK** (`docs/research/agent-frameworks.md`): only fully open-source frameworks are considered, and Mastra ships source-available enterprise code with telemetry on by default, while the Agents SDK sends traces to OpenAI by default.

## Consequences: models without the Tool loop

Models that can't call Tools, and small local models, get a single search with the Question's text instead, the results added to the Question context. When there are Blocks above the Question, the model first makes one short call to rewrite the Question into one self-contained search query, so "what about its limitations?" searches for what "its" means; with nothing above, or if the rewrite fails, the Question's own text is searched.

- **The engine searches again in the Documents' language for them** (`searchLanguage` in `src/core/answers/engine.ts`). When some Documents to search are in a language the Question isn't in (by `detectLanguage`; a Question too short to tell is known not to be Chinese, Japanese or Korean when it has none of their scripts), one short call translates the query into the most common such language, and that is searched too. The Passages of both are given once each, ranked alternately, so a small window keeps the best of each. In a library in two languages every such Answer pays that call and a second search. If the translation fails or comes back empty, only the first search counts.
- **Small local models cite with structured output** (#67, 2026-10-09). An Ollama model with fewer than 7 billion parameters, by the size Ollama reports, answers as a model without Tools does, even when it can call them: one search, then the Answer and its Citation records as one JSON object, with the engine placing the markers it leaves out (`citingMode` in `src/core/providers/ollamaModels.ts`). Why: in the loop, small models search but don't call `cite` (qwen3.5:4b gave no Citation on 10 Questions, Llama 3.2 3B none on 8), while in structured output qwen3.5:4b gave records with every Answer of a 20-Question probe. Lower temperature, stricter instructions, a fix-up request, a cap on quotes and thinking did no better.
  - **Its records are read as meant** (`CiteOptions` in `engine.ts`), since one request gets none of the feedback `cite` gives a model in the loop: a marker ("[^1]"), a Passage's number or its id with more ("P1 (p. 9)") names that Passage; a record naming no Passage it was given cites the first given Passage whose pages hold its quote; and a quote not on its record's pages is cited on the page, or two consecutive pages, of the named Passage that hold it word for word. A record never moves outside the Passage it names, and the check still reads the quote where it lands, so a quote that is nowhere stays "not found", and the Answer's end reports each record the core couldn't take (`tests/eval/smallModelCitations.test.ts`).
  - **A second chance at quotes not found** (2026-10-10). When the check doesn't find some of its quotes, the engine asks once more, in one request for all of them (at most 6), with each record's sentence, quote and Passage text (the 400 tokens nearest the quote), for an exact quote copied from that text, or none. A new quote replaces the old only when the check finds it on the pages it then cites, so a Citation can't get worse (`src/core/answers/quoteRetry.ts`). Why: the remaining misses are quotes reworded or stitched together, which `cite`'s feedback lets a model in the loop fix. It costs nothing when every quote is found, and never applies to cloud models or the loop; otherwise one request, capped at 100 output tokens a record, shown as "Checking quotes…" and reported (`quoteRetry`).
  - **The cost:** such a model searches once (twice across languages) and isn't offered Skills' or Connectors' Tools, which qwen3.5:4b handled unreliably too (it said it had closed an issue after the User denied the call); a Skill the User picks still applies.
  - **Unchanged:** models from 7 billion parameters up, those whose size Ollama doesn't give, and cloud models keep the loop; nothing measured would move them. `npm run eval` compares citing modes with `INCARNAMIND_EVAL_CHAT_NUM_CTX` and `INCARNAMIND_EVAL_CHAT_CITING` (`eval/README.md`).
