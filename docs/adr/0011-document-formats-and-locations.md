# Document formats, and where a Citation points

IncarnaMind reads more than PDF, Markdown and plain text, and a Citation's Location is the unit each format's readers use. Settled with the User on 2026-10-07, after the research in `docs/research/document-formats.md`.

**Formats, in waves:**
- **Now:** Word (`.docx`), PowerPoint (`.pptx`), Excel (`.xlsx`) and `.csv`, alongside PDF, Markdown and TXT.
- **Second wave, after the research:** `.html`, `.epub`, `.rtf`, OpenDocument (`.odt`, `.odp`, `.ods`) and the legacy binary Office formats (`.doc`, `.ppt`, `.xls`).
- **Out:** images and scanned pages that need text recognition.

**Locations:**
- PDF: one or two pages ("p. 4"), as before.
- PowerPoint: one or two slides ("slide 4"). Speaker notes count as part of their slide.
- Excel and CSV: a sheet and a range of rows ("Revenue, rows 12–14"). A CSV has a single sheet.
- Markdown: the section the quote sits under ("§ Methods"). Plain text: a range of lines ("lines 120–134"). This replaces citing the whole Document.
- Word: the section the quote sits under ("§ 2.1 Sensitivity"), as for Markdown. "§ Start" names text before the first heading only in a Document that has headings (`UnitLabel.beforeHeading`); a Word file with none is cited by its paragraph, counted from the file's start ("¶ 12"), or by its name alone. A preview's page breaks follow only explicit breaks, so its page numbers wouldn't match Word's, and a wrong page undermines a checkable Citation.

**Checking quotes from spreadsheets.** The cited rows' cells, joined in reading order, must contain the quote's words and numbers, the same way text quotes are checked. Number formatting is normalised first, so "4,812" matches "4812". Spreadsheet Citations are checked, not marked "can't check", because numbers are what analysts cite most and get wrong most.

**Reading and previews.**
- **Reading:** our own small zip-and-XML reader extracts text from `.docx`, `.pptx`, `.xlsx` and `.csv`, with no dependencies.
- **Word previews** are pages as the file sets them, with docx-preview (Apache-2.0): page size and margins, headers and footers, footnotes and endnotes, list numbering and bullets, fonts, colours, tables and images. Comments are notes in a margin beside the pages, as Word's markup area shows them, their text highlighted. A document that names no font is in Times New Roman, as in Word; Office's own fonts (Calibri, Cambria, Aptos), where they aren't installed, fall back to the app's bundled Source Sans 3 and Source Serif 4, never to the browser's Times.
- **PowerPoint previews** draw each slide as PowerPoint lays it out, with a renderer of our own on the same zip-and-XML reader (decided 2026-10-09). Each slide keeps its aspect ratio, scaled to the viewer's width, and its speaker notes are folded under it.
  - **Text stays real text,** read with the same code as the Units. A Citation's quote is washed on its slide, else in the slide's notes (which open), else the slide itself is marked.
  - **What is drawn:** theme colours and fonts, and layout, master and placeholder inheritance. Text with its runs, bullets, numbering and autofit. Pictures, cropped and clipped to their shape. Preset and custom shapes with gradient or picture fills, lines, arrowheads and shadows. Groups. Tables, including PowerPoint's default table style, which files leave out. Bar, column, line, area, pie and doughnut charts, drawn from their cached values with the file's own number formats. SmartArt, from the drawing PowerPoint saves beside it. An embedded object's picture.
  - **What falls back:** another kind of chart becomes a labelled box with its figures. A picture a browser can't show (EMF, WMF, TIFF) becomes a labelled box. A slide that can't be read, or a deck, is shown as the outline it was before (title, text, tables, images, notes).
  - **The Content-Security-Policy is unchanged:** pictures are `data:` URLs, and pictures linked from outside the file are never fetched.
  - **Fonts:** Carlito (OFL-1.1), which has Calibri's metrics, ships for decks set in Calibri, so their lines break where PowerPoint breaks them.
- **Excel previews** are the workbook as Excel shows it, read by our own reader in the same pass as its text: fonts, fills, borders, alignment and wrapping, rich text, merged cells, column widths and row heights, hidden rows and columns, frozen panes, gridlines on or off, notes, and values in their own number formats (dates, times, percentages, currency, accounting, scientific, fractions, colours and conditions). Pictures are shown; a chart is a labelled placeholder unless the file keeps a picture of it. Sheet tabs are at the bottom, and the cited cells are washed. Only the rows in view are drawn. What is indexed and quoted is unchanged (ISO dates, the plain number for formats it doesn't know): the look is for the eye only.
- **CSV previews** are a plain grid, its columns fitted to their values.
- **Markdown previews** are formatted, as GitHub renders them, by our own reader, so every rendered character maps back to the file and the quote is washed where it is: headings, lists (nested, numbered, tasks), tables, quotes, code highlighted by its language, links, and pictures beside the file. The main process serves those only from the file's own folder or below it, and only images; pictures from the web aren't loaded and show a placeholder. "Source" shows the text as written. **Plain text** stays plain, in the Mind's serif, or monospaced when it reads as code.
- **Second wave:** we read text with our own code where the format is simple (HTML, EPUB, RTF, OpenDocument), and show text-only previews. The legacy binary formats are decided when we reach them. SheetJS, now published only from its own site, is the likely route for `.xls`.
- **LibreOffice:** not used in v1. It is a separate 285 MB+ install, with frequent security advisories in its importers. Later, at most, it could give an optional exact-layout preview when it is already installed, but never the Locations Citations point at.

## Considered options

- **Every format now**, including legacy and OpenDocument: more coverage, but those likely need LibreOffice, which the research is weighing.
- **LibreOffice for every Office format**: exact layouts and real Word pages, but a large separate install with a poor security record for opening untrusted files.
- **Pages for everything**: one unit everywhere, but slides, sheets and Markdown have no pages their readers would recognise.
- **Spreadsheet Citations marked "can't check"**: simpler, but it leaves unchecked the claims most worth checking.
- **A library to read workbooks' styles** (2026-10-09, after `docs/research/vscode-previews.md`): `hucre` (MIT, no dependencies, about 43 KB gzipped) drew the fixture workbook about as our reader does, but not frozen panes. Our reader also covers hidden rows and columns, row heights, rich text, pictures, notes and Excel's number formats. It reads the look in the same streaming pass as the text, under the same row, cell and zip-bomb limits, and adds nothing to the app. `numfmt` (MIT) stays the fallback if our number formats fall short. `@silurus/ooxml` draws on a canvas, with no text layer for cells (its policy and size are under the PowerPoint option below).
- **A Markdown library** (markdown-it and the like): fuller CommonMark, but its HTML has no map back to the file below the block, so a quote couldn't be washed where it is.
- **A PowerPoint library instead of our own slide renderer** (compared 2026-10-09 on the fixture deck and three python-pptx decks, in the app's Electron):
  - **`@silurus/ooxml` 0.88.0** (MIT) parses in Rust compiled to WebAssembly and draws on canvas, with a transparent text layer over it.
    - **It runs under the app's exact policy** when its worker ships as a file: the parse and the drawing run in a module worker loaded from a file, which the page's policy doesn't govern. Only its fallback, an inline `blob:` or `data:` worker, would need `'wasm-unsafe-eval'` and `worker-src blob:`, so it would never need its own frame or a looser policy.
    - **Its fidelity is close to ours:** it draws shadows and charts' axes as the file sets them. It lost a chevron's label and a dark theme's chart text, and has no Calibri metrics.
    - **It costs** about 4.5 MB (1.8 MB of it WebAssembly) against our 64 KB. It took 106–162 ms to its first slide, against our 16–57 ms.
    - **Its quote highlight** would sit on an invisible layer over canvas glyphs, not on the text the Units were read from.
    - **It is young:** one maintainer, written by AI agents by its own README, 153 releases in six months.
  - **`@aiden0z/pptx-renderer` 1.3.0** (Apache-2.0) needs `blob:` images, cuts tables after their second row, and fetches linked pictures while a slide draws (its issue 32).
  - **`pptx-preview`** has no source and non-OSI terms. **PPTXjs** is jQuery and JSZip 2, untouched since 2022.

## Consequences

- **Units.** Each row of `document_pages` is now a Unit (migration 22): `page` is its number, and `kind`, `label` (JSON) and `anchors` (JSON) say what it is. PDFs keep their pages; a TXT or Markdown file stored whole becomes Unit 1 of kind `text`, so the old versions Citations quote stay checkable.
- **Processing.** `PROCESSING_VERSION` is 5, but only kinds whose Units changed are processed again at startup (`CURRENT_SINCE`): Markdown and TXT, not PDFs, whose Passages and vectors stay.
- **Block sizes.** A spreadsheet or CSV Unit holds up to 100 rows and about 1,600 characters (about 400 tokens), and every block after a sheet's first repeats the header row, so a Passage of about 500 tokens takes in a block or two and knows its columns. Passages never run from one sheet into the next. A plain-text Unit holds up to 50 lines and about 4,000 characters; a Word or Markdown section is split into parts past 6,000 characters. At most 20,000 rows (500,000 cells) of a workbook or CSV are read; the grid says so when it stops.
- **Size limits for Office files** (added 2026-10-10, #77): a Word, PowerPoint or Excel file over 500 MB is refused before it is read, and reading stops once a package's parts have inflated past 1 GB together. Both fail the Document as "too-large", with "Too large to open (limit …)". The per-part limits (64 MB read whole, 256 MB for a streamed sheet) are unchanged.
- **Spreadsheet values** are stored as Excel shows them ("£350,200", "4.2%", ISO dates), and quotes are matched with number formatting normalised, so a raw "350200" matches too.
- **A workbook's look** is read only for the preview (`readWorkbook`'s `layout`); processing doesn't read it, so no Document is processed again for it.
- **A Markdown file's pictures** come from the Document protocol under the Document's own URL (`documentImageUrl`), checked by the core (`openDocumentImage`): the path written in the file, resolved with links followed, inside the file's folder, an image's extension, at most 20 MB. The viewer turns them into `data:` URLs, so the Content-Security-Policy is unchanged.

## Amendment: Word comments are read, and table rows and a slide's figures are found however they are written (2026-10-10, #76)

Asked for in #76: the every-format evaluation's three false "not found", and Word comments, which the preview showed but nothing searched or cited.

- **Word comments** are read into the section their reference mark is in, where the preview shows their note, after the section's own text: each after a blank line, anchored as "comment" and its id, its author named in the section's label (`UnitLabel.comments`). A comment with only its range's start is read where the range starts; one anchored in a footnote, into the notes' section; one anchored only in a header or footer, which aren't read, is left out. So comments are searched, and a quote of one is cited at its section, its Location saying it is a comment by its author: "§ 2 Costs, comment by Reviewer", "§ 2 Costs，Reviewer 的批注" ("comment" alone when the file names no author). A Passage the model reads marks where each comment starts ("[comment by Reviewer]"), as it marks a slide's speaker notes. The viewer washes the quote in the comment's note in the margin, the Citation's mark between the page's text and the note.
- **Processing version 7** processes Word Documents again at startup (`CURRENT_SINCE.docx`), for their comments; the other kinds are left as they are.
- **Table rows written with or without their pipes.** A pipe that breaks a table's cells, a lone "|" with whitespace or a line's start or end beside it, reads as a space, in the quote and the text alike and for matching only (`findQuote`, `src/shared/quoteMatch.ts`): a Markdown row is found without its pipes, and a slide's or a Word file's row, stored with tabs between its cells, with pipes between them. A pipe inside a word ("a|b") or doubled ("||") stays a pipe. Indexing is unchanged.
- **A slide's figures.** A chart's figures are stored as the values the file caches ("Jun: 1560"), but drawn, and so quoted, in its number format ("Jun: 1,560"). A slide's quote that isn't found as it is is looked for again with number formatting normalised, as a sheet's rows always are; a quote found as it is stays found, so a slide's text keeps its stricter matching where it already matched. Only slides: PDF pages, sections and lines keep their numbers as written.
- **Unchanged:** a quote whose words or digits aren't on the cited Unit is "not found", with pipes or without, and a figure that differs isn't found however it is written.

## Amendment: Web pages, saved by their address (2026-10-10, #261)

- **A web page is a Document of its own kind,** "Web page", added by its address, not as a file. It is fetched once, from this computer: http or https only, within 20 seconds and 10 MB, anonymously, and nothing it links to or embeds (pictures, scripts, frames, trackers) is loaded. Its readable article is found with Mozilla's Readability (Apache-2.0) in a linkedom DOM (ISC), and kept as a snapshot in our own XHTML: headings, paragraphs, list items, quotes, code and tables, links to web addresses, and each picture as its description only. The snapshot is the Document's file; its title, address, site, author and publication date are in its head, and when each version was fetched is stored beside it (migration 47).
- **Location:** the section a quote sits under, as for Markdown, and the paragraphs it covers, counted from the section's heading: "§ History, ¶ 3", "§ 历史，第 3 段" ("§ Start" before the first heading). The Units are sections; the paragraphs are their anchors (`UnitLabel.paragraphs`), so only the label names them, and a model's "§ History, ¶ 3" names the section.
- **Checking and versions:** the check reads the stored text of the version a Citation quotes, so it still works when the live page changes or disappears. "Fetch again" writes the page as it is now over the snapshot: a page that changed is a new version, as a changed file is (ADR-0010), and one that didn't stays the same version, fetched later.
- **Refused:** a page that can't be fetched (offline, not found, behind a sign-in, too large) isn't saved, and says why with "Try again"; nor is one that is mostly not text (a video, an app) or a file that isn't a web page.
- **The viewer** draws the snapshot with DOM calls, never as markup, from the same reader that indexed it, and highlights the quote in the cited section. "Open the live page" opens the address in the User's browser.
- **Unchanged:** an `.html` file on disk is not a web page Document; HTML files stay in the second wave.

## Amendment: Transcripts, as WebVTT, cited by time (2026-10-11, #136)

- **A Transcript is a Document of its own kind,** "Transcript", in WebVTT (`.vtt`): a Meeting's, made on this computer as it records, and any `.vtt` file the User adds. One cue is one stretch of speech: its start and end, its words, and its speaker as a voice span: "Me", "Them" or "Speaker ?" on a live Meeting's lines from the first (`<v Me>`, #941), a person's name (`<v Dana>`) once speakers are told apart (#138, #140). A stretch nothing was transcribed for is a `NOTE gap <from> to <to> <reason>` block: the transcription process restarted after a crash, the computer slept, IncarnaMind was closed, or the audio was deleted before it could be transcribed. WebVTT players ignore notes; the viewer shows them; they are never indexed. Read by our own reader (`src/core/documents/formats/vtt.ts`), with no dependency.
- **Units** are blocks of cues in time order, at most 40 cues and about 1,600 characters, as a block of rows is, so a Passage holds one or two. Each cue is a line of the Unit's text, anchored by its times (`t754000-761500`); a Unit's label gives where its first cue starts and its last ends, and who said each cue where the file says.
- **Location: a range of time,** from the start of the cue a quote starts in to the end of the cue it ends in, in ms from the Transcript's start (`{ kind: "time", from, to }`). Its label is the clock time the quote starts: "14:26", "1:02:05". The model reads each cue with its time, and its speaker where known, before it ("[14:26 Dana] …"), and may name a time as a Citation's Location ("14:26"); a quote that runs over two cues is found across them.
- **Checking:** against the stored text of the version a Citation quotes, as for every format: the audio is deleted within a day, the text stays. A Transcript Citation's check is labelled the transcript's ("Quote found in the transcript at 14:26", "已在转写稿 14:26 处找到引文"), so it isn't taken for a page's; in Numbered, its chip shows the time instead of its number.
- **Where it is:** while its Meeting records, in the data folder's `Transcripts/`, indexed again as lines come (every 20 seconds at first, every two minutes once it is long, as each indexing keeps a version until the next start unless a Citation quotes it), even while other Documents wait for the recording (#135); at Stop, finished there and kept in the Library, keeping its id, Folder and Citations (#763: nothing is written to the Output location and no `.vtt` name is shown; the speaker pass rewrites the same file). A .vtt file the User adds is a Document of theirs, in its own place, as any file is. A Meeting with nothing transcribed saves none. A Transcript is a source IncarnaMind saved, as a web page is: checks count it as evidence.
- **Processing:** a new kind, so nothing else is processed again (`CURRENT_SINCE.transcript` is 7, the current version).

## Amendment: A workbook's cells keep their number beside how they show (2026-10-12, #435)

A calculation over a cell should use what Excel computes with, 0.04213, not the 0.042 that "4.2%" shows. The shown text is still what is stored, searched and checked; the number is kept beside it.

- **Where:** a workbook's rows Unit label gains `values`, the number stored in each cell whose shown text isn't that number written plainly (Excel's General rendering), by cell reference: `{ "C12": 0.04213 }`. It is sparse, so a sheet of plain numbers adds nothing; a date stays its ISO text and keeps no number. It is part of the Unit's label (JSON in `document_pages.label`), so no migration. A block lists only the cells of its own rows, not of a repeated header row.
- **A CSV** keeps none: its cells are their text.
- **Unchanged:** the Unit's text, its anchors and Passages, so the Citation check reads the shown text as before, and the viewer, which reads the file.
- **Asking:** `cellNumber(label, ref)` (`src/shared/units.ts`) gives a cell's number from a Unit's label, and the core's `readCellNumber(documentId, sheet, ref)` from a Document's current version, for the Tools that calculate over cells. It is not on the bridge.
- **Processing version 8** processes Excel workbooks again at startup (`CURRENT_SINCE.xlsx`), to gain the numbers; other kinds are left as they are.

## Amendment: scanned pages are read on this computer (2026-10-12, #397)

A scanned PDF had no text, so it couldn't be searched, asked about or cited. Its pages are now read with text recognition (OCR), on this computer. Photos and image files as Documents stay out, as does a cloud model for pages local OCR reads badly.

- **Which pages:** a PDF page with too little text for its size (fewer than 100 characters on an A4 page, in proportion on others) whose pictures cover at least half of it. A page of text is left as it was; so are a blank page, a drawing, and a scan that already has a text layer. A mixed PDF keeps its text pages as they were.
- **What reads them:** PaddleOCR's PP-OCRv5 mobile models (Apache-2.0) on onnxruntime-node, which the app already ships, in an Electron utility process. It reads Simplified and Traditional Chinese and English alike, the same on macOS, Windows and Linux. It was chosen on a scanned-page test set (`tests/fixtures/scans`) against PP-OCRv4 mobile, PP-OCRv5 server, macOS Vision, Windows.Media.Ocr and Tesseract (`eval/ocr/README.md`). Its two files, 21 MB, are pinned with their sizes and SHA-256 hashes and downloaded once, the first time a scanned page needs reading. Nothing of a scan is sent anywhere.
- **Its text is the page's Unit,** like any page's: kind "page", the same Location ("p. 4"), searched and cited as any other. Its label records what read it (`UnitScan.reader`, "PP-OCRv5 mobile/1") and the words it was unsure of; its anchors are its lines, in reading order ("line3"), each with its box on the page, as fractions of the page (`Anchor.quad`). A page is levelled by its lines' slant and read row by row, so a table's rows stay together; a page of two columns of text is read one column after the other. No migration: all of it is in the Unit's label and anchors.
- **Citations** of a scanned page are checked like any other, against the text stored. The card says "Text read from a scan" (从扫描件识别的文字) and marks the words of the quote the reading wasn't sure of, so the User looks at the page before trusting them. The viewer lays the text over the page's picture, line by line, so a quote is washed where it is on the picture, and the text can be selected.
- **Versions (ADR-0010).** When how pages are read improves, a PDF's scanned pages are read again (`SCAN_CURRENT_SINCE`, processing version 9 for the first reading), except the pages a Citation quotes or a feature retains: those are kept as they were read, so the Citation stays found. They keep the older reader in their label, so a later reading reads them once nothing quotes them. Processed again into the same Passages, a PDF keeps its Passages and their vectors.
- **Progress and failures:** the Document's status says "Reading 12 scanned pages…" while it is read, one page after another, newest Documents first. Pausing its Linked folder stops it between pages, and resuming goes on without reading again the pages already read. A page that can't be read (the model couldn't be downloaded, or failed on it) is named, "Scanned pages 3 and 7 couldn't be read", with Retry, which reads only those pages; the pages that were read are searched meanwhile. Once the model downloads after a failure, they are read by themselves.

## Amendment: a scanned page is read upright (2026-10-26, #1819)

A PDF's `/Rotate` and a scanner's own pixels can leave a displayed page a quarter-turn away from its reading frame. Recognition and layout now use an upright reading picture, including pages whose sideways source picture has no useful metadata.

- **Detection:** read the displayed picture first. Horizontal detected line boxes and confident recognition keep it after one pass. Otherwise try the other quarter-turns, with `/Rotate` as an ordering hint rather than a turn to undo blindly. Detection geometry, recognition confidence and a comparable amount of recognized text choose the result; an ambiguous page keeps its first reading.
- **Coordinates:** recognition, slant, rows, columns and cell gaps are all computed in the reading picture. Only the final anchor quads are inverse-mapped, to fractions of the original displayed page, so the viewer and Citation highlights stay on the quoted words. `UnitScan.turn` records the reading turn (omitted at 0), which Verify uses to reconstruct reading geometry for table extraction; it does not change the displayed anchors. Saved web pictures are unchanged.
- **Processing version 12** reads affected PDF scans again under reader `PP-OCRv5 mobile/2` (`SCAN_CURRENT_SINCE`). As above, a page retained by a Citation or another feature keeps its earlier reading and anchors until nothing retains it. No database migration; text pages and saved web picture readings are unchanged.

## Amendment: pages web search reads (2026-10-12, #128)

- **Saved through #261's path,** as Web page Documents with the same snapshot, Location ("§ History, ¶ 3") and check. A page already saved is used as it is, not fetched again, once its address passes the same check as a fetch (so a page the User saved from their own network isn't read by web search). A new one is filed in the Folder of the Mind or conversation the Question was asked in.
- **A fetcher for the public internet only.** Web search fetches with its own fetcher, which keeps #261's limits (20 seconds, 10 MB, no cookies, the page alone) and adds: an undici `Agent` whose connect-time lookup gives only public unicast addresses (ipaddr.js's special-purpose ranges, IPv6 in 2000::/3, no IPv4-mapped address), so DNS rebinding finds nothing to connect to; a host written as an IP address checked before each request; at most 5 redirects, each checked again; no proxy. A page it refuses says so ("it's on this computer or a local network"). Pages a User adds by address keep #261's fetcher, which reaches local addresses.
- **Read soon.** A web page's processing goes ahead of other Documents', and of a recording's hold (#135), as an Answer waits to read it.

## Amendment: a provision's Location, "§ 240.10b-5(b)" (2026-10-12, #304)

Find sources adds regulations and statutes (the eCFR, GovInfo) as Markdown, one section per provision and per paragraph it numbers (ADR-0018).

- **No second "§".** A provision's heading is written as it is cited, without its own "§": "240.10b-5 Employment of manipulative and deceptive devices", "240.10b-5(b)", "78j(a)(1)". The Location's label adds the "§" as it does for every section, so it reads "§ 240.10b-5(b)" once, in English and Chinese alike. The Document's title names the code ("17 CFR 240.10b-5 …", "42 U.S.C. § 1983 …").
- **A paragraph's own "(1)".** A model may name a section by a Location such as "§ 243.100(a)(1)". A heading that matches it as written is that section; only when none does is a trailing "(2)" read as the second section of a name. A closing parenthesis that closes one in the label is kept ("§ 240.10b-5(b)"); one that wraps the whole Location is dropped ("(§ Methods)").
- **Unchanged:** Markdown's Units, Passages and the quote check. No processing version.

## Amendment: a Word file imported as a Mind, kept to write back into (2026-10-12, #104)

A .docx can also be imported as a Mind, from "Import a Word file…" in the + menu or a Word file dropped on a Mind: its text becomes Notes the User edits, and export writes the edits back into the original (#105). It isn't added to the Library; a file dropped on a Mind can be added as a Document instead.

- **Editable:** headings (by style name or outline level, through the style a style is based on), paragraphs with bold, italic, underline, strikethrough and highlight, lists numbered through the paragraph or its style (nested by level, starting where Word's numbers are), tables with merged cells, inline pictures a browser can show (up to 10 MB each, 64 MB a file) and hyperlinks. Typed numbering ("1.", "一、") and bold lines stay text. Fonts, sizes and colours aren't shown, and stay in the package.
- **Kept as is, shown in place** (`wordAtom`, `wordBlock`; ADR-0003, amended): fields (their result), content controls, text boxes, shapes, SmartArt, charts, equations, embedded objects, floating pictures, comments and other people's tracked changes (read-only until #108), the first header and footer (Blocks at the top and the foot), and any element this version doesn't know. Text boxes, controls and fields are read for Questions with the rest; a comment and a deletion not. A section break shows as a line across the text; invisible: bookmarks, other ranges and column breaks. None can be edited inside, and deleting a section break is a change like any other, which the note's ⌘Z takes back. Footnotes and endnotes are the Note's own footnotes, and page breaks its own page breaks (#746; ADR-0003, amended): a note whose text a footnote can't hold (a table, a picture, someone's tracked change) or with a mark of its own is kept as is. Each says where its XML is: an element by its name and its place among those of that name in the part ("w:sdt#3"), a run of runs for a field ("w:r#40..w:r#44"), or a part ("word/header1.xml").
- **Where each paragraph came from:** its `w14:paraId` when no other paragraph shares it, else its place in the part, and its fingerprint as imported (`wordSources`). Nothing is dropped without being counted: the import's report says what became editable and what is kept as is, by kind.
- **The original package** is kept in the data folder, "Word imports/<sha256>.docx" (migration 75), so export still works after the User's file moves or is deleted; it goes once no Mind keeps it, after the last is deleted permanently.
- **Refused before a Mind is made, with the reason:** a .doc, a .docm or a package with macros, an encrypted file, Strict Open XML, a damaged package or XML (a DOCTYPE included), and a file over the size limits for Office files.
- **Whose document:** the import screen asks. A file with tracked changes or comments is someone else's by default, naming their authors; someone else's makes every Block third-party text (#78).
- **Long files** are read whole before the Mind is made (a 300-page file in about a second), then written into it in batches that double in size, so the editor draws it a few times rather than hundreds; the Mind says how far it has got and can't be edited until it is done. An import a quit cut short goes on at the next start.
- **Checked on the Word corpus (#84):** `npm run eval:word` imports each file and checks that the editor takes every node and that every paragraph's text is kept; all 238 files pass, the two in Strict Open XML refused as above.
- **Unchanged:** Word Documents are read and previewed as before.

## Amendment: a Mind imported from Word, exported back into its file (2026-10-13, #105)

Exporting to Word a Mind imported from a .docx writes into the package kept at import, not a new document, so the User's file comes back as it was wherever they didn't change it (#74).

- **Untouched entries are copied as they are,** compressed bytes and all, by the one ZIP module (#77). Only the parts the Mind changed are written again: the main document part and, when something new needs them, the styles, numbering, footnotes, relationships and content types. Each is spliced into its own text by the offsets the reader records, so whatever an edit doesn't reach keeps its bytes. The document's start tag, with its namespaces and `mc:Ignorable`, is never rewritten.
- **Matching.** The document's paragraphs, tables and kept-as-is Blocks are matched with the Mind's by where each came from (the places #104 records). Those the Mind kept in order stay where they are, byte for byte unless edited; those it deleted go; new and moved ones go after the one before them. A table keeps its rows and cells and is written into cell by cell; one whose rows or columns changed is written again, each row and cell from the one it was, with its properties and the content controls around it.
- **An edited paragraph is written into its own XML** (#104 left open how formatting comes back). Its text as imported and as it is now are compared by words, as Proposals compare text. Each child of the paragraph whose text was all kept is copied as it was; one with an edit is written again run by run, each character with its own run's properties. Typed text takes the formatting of what it replaces, else of the character before it, as typing in Word does, and the editor's marks (bold, italic, underline, strikethrough, highlight, links) are set or removed in those properties alone: a font, a size or a colour the editor doesn't show stays. The paragraph's own properties change only where the Mind changed what it is: a heading's level (the document's own heading style, or its own outline level), a list it moved into or out of, a section break it holds.
- **New Blocks** are written by the native writer into the document's own styles (found by Word's names for them, else added with the native export's definitions, FootnoteText and FootnoteReference among them), its lists (new definitions after its own, new lists after its lists) and its footnotes. A new paragraph takes the properties of the plain paragraph before it, and its text that paragraph's last formatting, as pressing Enter there would; a new list item, its neighbour's. Citations are in the Mind's citation style, as in the native export: Numbered's as footnotes, a style's in the text or as notes, with its Bibliography at the end.
- **What the import kept as is goes back as its original XML.** A copy of one is written as its text, except what has no id that could clash (a field, an equation, a symbol, a page break). A mark that comes in pairs (a bookmark's start and end, a comment's range and its mark) is left out when its other half is gone, as Word would otherwise repair the file.
- **Footnotes and endnotes** (#746) are written back into `footnotes.xml` and `endnotes.xml`. A note the User edited is written again in its own element, its id and start tag kept, each paragraph written as an edited paragraph of the body is, from the one it was; every other note is byte for byte the file's. A note whose mark is gone from the Note goes from its part, unless the User's edits are tracked and it stays as their deletion. An endnote stays an endnote; a copy of a note's mark is a new footnote. A page break added in the Note is Word's page break where it was put.
- **Headers and footers** (#104 left this open too): deleting their Block from the Mind doesn't take them out of the file. They are the pages' layout, kept as they are, and the result line says so after saving.
- **Word's rules.** Ids stay unique and below 0x80000000: new footnotes and drawings take ids the document hasn't used. XML new in a part declares the namespaces its place doesn't bind.
- **Footnote ids aren't renumbered** (decided 2026-10-13: A, by the owner). A new footnote's id is above the document's own, so Word, which finds a footnote by its id, shows each in its place and renumbers them when it saves. LibreOffice instead gives the marks the footnotes in the order of their ids, so it shows a new footnote whose mark comes before one of the document's own with the wrong text; that limit is accepted. The options were A, keeping the ids, and B, renumbering every footnote in the order of its mark, which LibreOffice would show right but which changes the marks of paragraphs the User didn't edit, which this keeps byte for byte.
- **Checked before anything is saved.** Every part written is parsed again with `@xmldom/xmldom` (MIT, 0.9.12, pinned), a conforming parser, unlike the reader's own; it is never given a part the reader hasn't already refused a DOCTYPE in. A part that isn't well-formed XML with every prefix bound stops the export, naming the part, and nothing is saved; so does a part whose text doesn't encode back to its bytes. The parts themselves are read with the reader's own parser, whose places the import recorded.
- **What can't be kept is said before saving:** someone's comment or tracked change on text the User deleted, a copy written as text, an edit next to a field that can only be written as it was, a digital signature that no longer matches. The result line lists it with Export anyway, and nothing is saved until the User chooses it. Parts IncarnaMind doesn't know are copied as they are and listed in the report.
- **Saving.** A new file never replaces another (#124), so there is nothing to ask before replacing; it is written to a temporary file beside its name, which then takes the name at once, so no one sees it half written.
- **Checked on the Word corpus (#84):** `npm run eval:word` exports each file as it was (every entry byte for byte), then after a scripted edit (a word changed, a paragraph with a Citation added): only the parts the edit needs change, every other paragraph and table of the body and the document's start are byte for byte, the Citation is a footnote, the package passes the checks Word's repair prompt is about, and the export opens in LibreOffice headless. `npm test` also makes edits of every kind on the committed set. All 238 files pass, the two in Strict Open XML refused at import as before.
- **Unchanged:** a Mind not imported from Word exports to a new document as before (its bytes pinned by the tests), and imported Minds export to Markdown, PDF and HTML as any other.

## Amendment: a saved web page keeps its article's pictures (2026-10-14, #756)

The amendment for #261 said a web page loads nothing it embeds. A chart, a table drawn as a picture or a scanned exhibit was then lost: it couldn't be shown, read or cited. Now the article's own pictures are saved with the page.

Its header is checked first (its type, and its size within the 50-million-pixel cap, a GIF's first frame and an AVIF's largest image included). It is decoded in the model's own process, never in the app's, so a file that breaks the decoder takes only that process down, and the picture keeps its description. A Document whose reading stopped the app anyway isn't read again at the next start: it says so, and waits for Retry.
