# Document formats, and where a Citation points

## Context

IncarnaMind reads more than PDF, Markdown and plain text. Every Citation must be checkable, so its Location is the unit each format's own readers use, and its quote is checked against the text stored for the version it quotes. Files are untrusted and the app stays small. The formats and Locations were settled with the User on 2026-10-07, after the research in `docs/research/document-formats.md`.

## Decision

### Formats

- **Read now:** PDF, Markdown, plain text, Word (`.docx`), PowerPoint (`.pptx`), Excel (`.xlsx`), `.csv`, RTF and HTML files (#762), pictures (`.jpg`, `.jpeg`, `.png`, `.webp`, `.heic`, `.heif`; #762), Web pages saved by their address (#261) and Transcripts in WebVTT (#136). A PDF's scanned pages are read by text recognition on this computer (#397). Scans and pictures were out at first; they came in because a scan with no text can't be searched or cited, and folders are full of pictures.
- **Second wave:** EPUB, OpenDocument (`.odt`, `.odp`, `.ods`) and the legacy binary Office formats (`.doc`, `.ppt`, `.xls`). Where a format is simple we read its text with our own code and show a text-only preview. A reader for the legacy formats is decided when we reach them; SheetJS, now published only from its own site, is the likely route for `.xls`. Until then the User's own LibreOffice can convert them (below).
- **Out:** understanding a picture beyond its text, any promise for handwriting, and a cloud model for pages that local text recognition reads badly.

### Locations

| Format | Location | Example |
|---|---|---|
| PDF, its scanned pages | one or two pages | "p. 4" |
| Picture | its one page, its lines as regions | "p. 1" |
| PowerPoint | one or two slides; speaker notes count as part of their slide | "slide 4" |
| Excel, CSV | a sheet and a range of rows; a CSV has a single sheet | "Revenue, rows 12–14" |
| Markdown, Word, RTF, HTML file | the section the quote sits under | "§ Methods" |
| Plain text | a range of lines, not the whole Document | "lines 120–134" |
| Web page | the section, and the paragraphs counted from its heading | "§ History, ¶ 3" |
| Transcript | a range of time, labelled with the time the quote starts | "14:26" |

- **Word is cited by section, never by page:** a preview's page breaks follow only explicit breaks, so its page numbers wouldn't match Word's, and a wrong page undermines a checkable Citation. "§ Start" names text before the first heading, only in a Document that has headings (`UnitLabel.beforeHeading`); a Word file with none is cited by its paragraph from the file's start ("¶ 12"), or by its name alone. A quote of a Word comment is cited at the comment's section, as a comment by its author ("§ 2 Costs, comment by Reviewer").
- **A Web page's** Units are its sections ("§ Start" before the first heading) and its paragraphs are their anchors (`UnitLabel.paragraphs`), so a model's "§ History, ¶ 3" names the section. A quote in a picture's text is "§ Results, figure 2".
- **A Transcript's** Location runs from the start of the cue the quote starts in to the end of the cue it ends in, in ms (`{ kind: "time", from, to }`); a quote over two cues is found across them.
- **A provision** (#304; ADR-0018) is written without its own "§", so the label's "§" makes it "§ 240.10b-5(b)" once. A heading that matches such a Location as written is that section; only when none does is a trailing "(2)" read as the second section of a name.
- **A deposition** (#1709) uses the `page` Location with optional printed `lines: { from, to }`; physical `from`/`to` still open the PDF's Units, so an older reader that ignores `lines` still opens the page.

### Checking quotes

- **Every check reads the stored text of the version a Citation quotes,** so it still works when the file, the live page or a recording's audio is gone.
- **Spreadsheet Citations are checked,** because numbers are what analysts cite most and get wrong most. The cited rows' cells, joined in reading order, must contain the quote's words and numbers, with number formatting normalised ("4,812" matches "4812"). Values are stored as Excel shows them ("£350,200", "4.2%", ISO dates).
- **Two more exceptions to exact matching** (#76; ADR-0009), for matching only (`findQuote`, `src/shared/quoteMatch.ts`): a pipe that breaks a table's cells reads as a space, so a row is found with its pipes or without them; and a slide's quote not found as it is is looked for again with number formatting normalised, because a chart's figures are stored as the file caches them ("1560") but drawn in its number format ("1,560"). Only slides: PDF pages, sections and lines keep their numbers as written.
- **Nothing else is forgiven.** A quote whose words or digits aren't on the cited Unit is "not found", and a figure that differs isn't found however it is written. Neither exception changes indexing.
- **Text read from a picture** is checked like any text, but its card says so and marks the words the reading wasn't sure of, so the User looks before trusting them.

### Reading and previews

- **Our own readers, with no dependencies,** extract every format's text but PDF's: a small zip-and-XML reader for Office files and CSV, a WebVTT reader, and RTF and HTML readers that keep headings as Markdown, so those files have a Markdown file's sections. The viewer reads each file with the same code that indexed it.
- **Previews never change the Content-Security-Policy:** pictures reach the page as `data:` URLs, and pictures linked from outside a file are never fetched.
- **Word** previews are pages as the file sets them, drawn by docx-preview (Apache-2.0), with comments as notes in a margin. Office's fonts, where not installed, fall back to bundled stand-ins (Carlito for the sans faces, Source Serif 4 for Cambria), never the browser's Times.
- **PowerPoint** previews come from a renderer of our own on the same reader (decided 2026-10-09; see Considered options), drawing each slide with what it inherits from its layout, master and theme. Text stays real text, read with the same code as the Units, so a quote is washed on its slide or in its notes. What it can't draw falls back to a labelled box, and a slide it can't read to an outline. Carlito (OFL-1.1) ships so Calibri decks break their lines where PowerPoint does.
- **Excel** previews show the workbook as Excel does, read in the same pass as its text, drawing only the rows in view. The look is for the eye only: processing never reads it, and what is indexed and quoted is unchanged.
- **Markdown** previews are formatted as GitHub renders them, by our own reader, so every rendered character maps back to the file and a quote is washed where it is. Its pictures come only from the file's own folder or below it (links followed), only images, at most 20 MB, checked by the core (`openDocumentImage`); pictures from the web aren't loaded. CSV is a plain grid, and plain text stays plain.
- **LibreOffice is never a reader or a preview in v1, and never gives a Citation's Location:** it is a separate 285 MB+ install with frequent security advisories in its importers. Later, at most, it could give an optional exact-layout preview where it is already installed. It is used only as a converter (#762): where the User's own LibreOffice is installed (never bundled, copied or downloaded), one action converts a copy of an old Office or WPS file headless, with a private profile, and the copy is added as a Document that says which file it came from and is read by our own readers. The original is never changed. Without LibreOffice, such a file is skipped with the plain next step.

### Word comments (#76)

Word comments are searched and cited. Each is read into the section its reference mark is in, after the section's text, with its author in the section's label (`UnitLabel.comments`). One anchored in a footnote goes into the notes' section; one anchored only in a header or footer, which aren't read, is left out. The model's Passages mark where each comment starts, as they mark a slide's speaker notes.

### Scanned pages and pictures (#397, #1819, #762)

- **Which pages:** a PDF page with too little text for its size (fewer than 100 characters on an A4 page, in proportion on others) whose pictures cover at least half of it. A page of text, a blank page, a drawing and a scan that already has a text layer are left as they are.
- **The reader:** PaddleOCR's PP-OCRv5 mobile models (Apache-2.0) on onnxruntime-node, which the app already ships, in an Electron utility process. It reads Simplified and Traditional Chinese and English alike on macOS, Windows and Linux, and was chosen on a test set of scanned pages (`eval/ocr/README.md`). Its two files, 21 MB, are pinned by size and SHA-256 and downloaded once, the first time a page needs reading. **Nothing of a scan or a picture is sent anywhere.** A HEIC picture is decoded by this computer's own decoder where it has one.
- **The text is the page's Unit,** cited as "p. 4" like any page. Its label records the reader (`UnitScan.reader`) and the words it was unsure of; its anchors are its lines in reading order, each with its box on the page (`Anchor.quad`), so the viewer lays the text over the picture and washes a quote where it is. All of it is in the label and anchors, so no migration.
- **Read upright** (#1819). A PDF's `/Rotate` or a scanner's pixels can leave a page a quarter-turn from its reading frame, so the displayed picture is read first and, unless it reads confidently, the other quarter-turns are tried; an ambiguous page keeps its first reading. Only the final boxes are mapped back to the displayed page, so highlights land on the quoted words.
- **Versions (ADR-0010).** When reading improves, scanned pages are read again (`SCAN_CURRENT_SINCE`), except pages a Citation quotes or a feature retains: they keep their reading, so the Citation stays found, until nothing retains them.
- **Failures** are named by page, with Retry, which reads only those pages; the others are searched meanwhile, and pausing a Linked folder stops reading between pages.

### Web pages (#261, #128, #756)

A Web page is a Document of its own kind, added by its address.

- **Fetched once, from this computer:** http or https only, within 20 seconds and 10 MB, anonymously, and nothing it links to or embeds (scripts, frames, trackers) except its article's pictures. Its readable article is found with Mozilla's Readability (Apache-2.0) in a linkedom DOM (ISC) and kept as a snapshot in our own XHTML, which is the Document's file (ADR-0010); when each version was fetched is stored beside it (migration 47). The viewer draws the snapshot with DOM calls, never as markup.
- **Versions.** "Fetch again" writes the page as it is now: a changed page is a new version, as a changed file is (ADR-0010). A page that can't be fetched, or is mostly not text, isn't saved, and says why.
- **Pages web search reads** (#128) are saved the same way, filed in the Folder of the Note or conversation that asked, and processed first, as an Answer waits to read them. A page already saved is reused only once its address passes the same check as a fetch, so a page the User saved from their own network isn't read by web search.
- **Web search's fetcher reaches only the public internet:** an undici `Agent` whose connect-time lookup returns only public unicast addresses (no special-purpose range, IPv6 only in 2000::/3, no IPv4-mapped address), so DNS rebinding finds nothing to connect to; a host written as an IP address checked before each request; at most 5 redirects, each checked; no proxy. Pages a User adds by address keep the first fetcher, which reaches local addresses.
- **A page's pictures** (#756) are saved with it, because a chart, a table drawn as a picture or a scanned exhibit would otherwise be lost. Only `<img>` inside the article, at the widest `srcset` size up to 1600 px, as PNG, JPEG, GIF, WebP or AVIF judged by their first bytes; not SVG (it can carry scripts) or `data:`, not under 64 px a side, not avatars, logos, icons or emoji, and not from a known ad or tracker host (`src/core/documents/web/adHosts.ts`). They are fetched once, anonymously (no cookies, no Referer), through the public-internet fetcher, within one 20-second limit for the page; at most 5 MB a picture, 25 MB and 60 pictures a page (a page over them keeps the first and says how many it left out). The Document protocol serves a page only the pictures its versions show. **Adding the page is the consent** (ADR-0022), and the add dialog says the pictures come with it and may come from the site's image servers.
- **Pictures are kept** in `Web pages/pictures/` by SHA-256, shared between versions and never written over, with a row per picture per version (migration 89), and go when no version of any page shows them. They are read by the scanned pages' model, decoded in its own process so a file that breaks the decoder never takes down the app, within a 50-million-pixel cap; a Document whose reading stopped the app anyway isn't read again at the next start, but waits for Retry. Their text is a block of its section ("figure2"), and never moves where a section is cut.
- **Keep the page as it looks** (#756) adds a PDF of the page as a browser shows it, as evidence of its look; the text stays what is indexed and cited. **It is off by default,** a box at the save and a setting, because the page's scripts and the other sites it draws from are loaded, so those sites see a visit; their tick is the consent (ADR-0022). Nothing else loads a page this way: not a save that doesn't ask, not Fetch again of a page not kept so, never a page web search saves, and no background work. A look asked for but not made before a quit is made once at the next start.
- **Its isolation:** a sandboxed hidden page of the main process (`src/main/pageLook.ts`), never one of the app's windows, with context isolation, no Node and no preload, in a session held only in memory and cleared after each page. Permissions, pop-ups, downloads, printing, sign-ins and navigation away are refused, WebRTC goes only through the proxy, and no site is given a client certificate, which on a managed Mac could be an identity in the User's name. Its only way out is a loopback proxy (`src/main/lookProxy.ts`) that answers only its own secret and connects only to public addresses it resolved and checked itself, so an intranet page can't be kept as it looks. Chromium may still look up a host it only prefetches, through the User's resolver, without connecting. Limits: 200 sheets, 50 MB and 30 seconds, after which it is given up; the page is destroyed either way. Kept in `Web pages/looks/` by SHA-256 (migration 91).

### Transcripts (#136)

A Transcript is a Document of its own kind, in WebVTT (`.vtt`): a Meeting's, made on this computer as it records, or a `.vtt` file the User adds.

- **One cue is one stretch of speech:** its start, end, words and speaker as a voice span (`<v Me>`, `<v Them>`, `<v Speaker ?>`, or a name the file gives). A stretch nothing was transcribed for is a `NOTE gap <from> to <to> <reason>` block, shown in the viewer and never indexed.
- **The speaker pass leaves the file as it is** (#138, [decided on #2839](https://github.com/IncarnaMind/IncarnaMind/issues/2839#issuecomment-6726913836)). Who it found spoke each line, and the names and moves the User gives, go into the Transcript's who's who, so no Citation of the Transcript needs checking again. A call's notes, written before the pass ends, name speakers as the lines read then ("Them" for everyone on the other side).
- **While its Meeting records,** it is in the data folder's `Transcripts/` and is indexed again as lines come: every 20 seconds at first, every two minutes once it is long, even while other Documents wait for the recording (#135). Each indexing keeps a version until the next unless a Citation quotes it. At Stop it stays there, in the Library, keeping its id, Folder and Citations; nothing is written to the Output location (#763). A Meeting with nothing transcribed saves none.
- **The audio is deleted within a day; the text stays,** and checks count a Transcript as evidence, as a saved web page is. Its Citations show the time, also on their check and in Numbered's chip, so they aren't taken for a page's.

### Record cites (#1709)

A record cite (a deposition's page and lines, an exhibit, a docket entry, a Bates number, a numbered paragraph, a recording's time, and `Id.` and `supra`) is checked against the exact place it names, not by searching the whole Document. Its grammar is one module (`src/core/recordCites/parser.ts`).

- **A cite is read whole, with its whole source,** so "Def.'s Ex. 7" never reaches a Document named only "Exhibit 7". A sentence of record cites alone belongs to the sentence before it, which it supports. A recording time needs its source's name, so a clock time in prose is not a cite, and a cite's numbers are not figures to tie out. A cite it can only read in part, or a short form with a pin it can't read, is Not found, never read without its pin.
- **`Id.` and `supra`** refer to the record item they follow in the Note's reading order; any other authority (a case, a statute, a rule, another `supra`, a Citation chip) ends the chain. A `supra` is a record cite only when its name is a record item's. An `Id.` with nothing before it is a record cite only when it names a deposition's page and lines, and is then Not found.
- **Deposition lines come only from a PDF's explicit layout** (standalone `Page N` over lines numbered from 1 with none missing), anchored at exact offsets. Anything less clear is an ordinary page, or the cite is Not found; labels never resolve by first match, so a PDF that isn't a transcript keeps its Passages.
- **Each cite keeps its own result** (Supported, Partly, Unsupported, Choose, Not found or Not checked) beside the sentence's, and a failed model call marks only its own cite Not checked. Finding the place is never a support claim. Ambiguity is a choice the card offers, never a silent first match or a background question. A Document's pages are read only once its name is the cite's, or the keyword index and printed page names say it may hold the cite's Bates number. The Check record lists every record cite without inflating sentence or Citation counts, and nearby evidence is labelled a suggestion, never the result.

### Word files as Notes (#104, #105, #107, #108, #734)

A `.docx` can be imported as a Note the User edits, and exported back into its own file, so the file comes back as it was wherever the User didn't change it (#74).

- **The original is also a Document,** unless the User unticks it. The Note is the working copy and is never cited; the Document is the file as received, cited like any other, and never evidence for the Note's own sentences. A newer file of the same name imported into the same Folder can become its new version. Export never changes the Document, and deleting either leaves the other.
- **Headings, paragraphs with their basic formatting, lists, tables with merged cells, inline pictures and links become editable;** typed numbering stays text. Footnotes, endnotes and page breaks are the Note's own (#746, ADR-0003). A long file is read whole first and written in growing batches; an import a quit cut short goes on at the next start.
- **What the editor can't represent is kept as is,** shown in place and never lost (`wordAtom`, `wordBlock`; ADR-0003): fields, content controls, text boxes, shapes, charts, equations, embedded objects, floating pictures, comments, headers and footers, and anything this version doesn't know. Each names where its XML is. The import's report counts what became editable and what was kept as is.
- **The original package is kept** in the data folder as `Word imports/<sha256>.docx` (migration 75), so export works after the User's file moves; it goes once no Note keeps it.
- **Refused before a Note is made, with the reason:** a `.doc` (LibreOffice can convert it), a `.docm` or any package with macros, an encrypted file, Strict Open XML, a damaged package or XML (a DOCTYPE included), and a file over the size limits for Office files.
- **Whose document:** the import screen asks. A file with tracked changes or comments is someone else's by default, and someone else's makes every Block third-party text (#78).
- **Export writes into the kept package** (#105). Untouched entries are copied byte for byte; only changed parts are written, and in them only what changed, matched by where each paragraph came from. New content is written in the document's own styles, lists and footnotes, as typing or Enter in Word would, and Citations follow the Note's citation style. Kept-as-is XML goes back from its place only when the hash recorded at import shows it is the file's own there; a copy (a note's mark, a page break, a picture) is written as the User's new content. Headers and footers stay when their Block is deleted: they are the pages' layout. Ids follow Word's rules (unique, below 0x80000000), and footnote ids aren't renumbered (see Considered options). Every part written is parsed again with `@xmldom/xmldom` (MIT, pinned) before anything is saved, and a part that isn't well-formed stops the export. What can't be kept (someone's comment on deleted text, a broken digital signature) is said before saving, with Export anyway. A new file never replaces another (#124), and is written to a temporary file first.
- **Review in Word** (#107). Changes still waiting always go out as tracked changes by IncarnaMind, so accepting all in Word gives what accepting all in IncarnaMind does. In a Note imported from Word, the User's own edits since import can go out as their tracked changes, under the name in Settings › General; with that on, nothing the User deleted leaves the file, and someone's comment or tracked change on deleted text stays inside the deletion. A table's column changes and a moved kept-as-is Block aren't tracked. With no change waiting and the options off, an export is byte for byte what it was before.
- **Comments by IncarnaMind** can mark AI text and what needs a look (a sentence or Citation that is Contradicted, Unsupported, Not found, Quote not found or Needs re-check, #900); a Citation whose quote was found, or that can't be checked, gets none. Comments on what needs a look are on by default for the User's own Notes.
- **Two choices are the User's to answer, once, never decided by an export:** whether to mark AI text (#1380; an older "on" switch is asked again, "off" reads as "leave"), and, in the Numbered style for Word and PDF, whether Citations are footnotes (the default) or `[n]` with one list of the Documents cited at the end, reusing the Bibliography's entries (#1600). A Citation in a change still waiting goes into Word as a tracked insertion and is listed; a PDF leaves it out. A Word file's own footnotes are untouched.
- **Comments on someone else's file are off by default** (#110), kept per Note, because they quote the User's Documents and name them, and that file goes back to the other side. Turning them on writes the same file again, never a second copy that could be sent instead. Such a file is exported under the original's name; the original is never touched.
- **Someone else's tracked changes** (#108) of text are Proposals (ADR-0003), accepted or rejected one by one or all of one person's, with Undo. Until accepted they aren't the Note's text, and accepting one isn't AI use. Changes that can't be Proposals (formatting, moves, a table's structure, a change holding more than text) are kept as is for Word. A change whose deleted words the User has edited since is out of date and can only be rejected; words the User types into their insertion are theirs. Export writes a change still waiting back as it was, with its author and date; one decided leaves no trace, as in Word. The Note doesn't record which way each went, so export reads it from the text.
- **Models and exports see their changes as changes** (#734), because reading them as accepted hid what the counterparty changed. A Question and `read_mind` read them inline with who and when; an author's name can't close or open a mark, and text that looks like a mark is escaped. PDF and HTML show them as Word's All Markup does, Markdown as CriticMarkup, unless the User exports "As if accepted".

## Considered options

- **Every format now**, legacy and OpenDocument included: those likely need LibreOffice.
- **LibreOffice for every Office format:** exact layouts and real Word pages, but a large separate install with a poor security record for opening untrusted files.
- **Pages for everything:** slides, sheets and Markdown have no pages their readers would recognise.
- **Spreadsheet Citations marked "can't check":** simpler, but it leaves unchecked the claims most worth checking.
- **`hucre` (MIT) for workbook styles** (`docs/research/vscode-previews.md`): it missed frozen panes, and our reader covers more in the same streaming pass, under the same row, cell and zip-bomb limits, adding nothing. `numfmt` (MIT) stays the fallback if our number formats fall short.
- **markdown-it or another Markdown library:** its HTML has no map back to the file below the block, so a quote couldn't be washed where it is.
- **`@silurus/ooxml` (MIT) for slides:** it draws on canvas, so a quote's highlight would sit on an invisible layer, not the text the Units came from; it is about 4.5 MB against our 64 KB, slower to its first slide, and young (one maintainer, 153 releases in six months). Other slide libraries cut tables, fetch linked pictures, lack source or are unmaintained.
- **Other text recognition** (PP-OCRv4 mobile, PP-OCRv5 server, macOS Vision, Windows.Media.Ocr, Tesseract): compared on the same scanned pages, `eval/ocr/README.md`.
- **Renumbering footnotes on export** (decided 2026-10-13): LibreOffice would show them right, but it changes the marks of paragraphs the User didn't edit. Accepted limit: LibreOffice shows a new footnote placed before one of the document's own with the wrong text.
- **A line in the model's instructions explaining change marks** (#734): it would lengthen every request, and Claude Haiku 5.5, GPT-6 Luna and gpt-oss read the marks correctly without one.

## Consequences

- **Units.** Each row of `document_pages` is a Unit (migration 22): `page` is its number, and `kind`, `label` (JSON) and `anchors` (JSON) say what it is. PDFs keep their pages. A TXT or Markdown file once stored whole became Unit 1 of kind `text`, so the old versions Citations quote stay checkable.
- **Unit sizes and reading limits.**
  - Spreadsheet or CSV: up to 100 rows and about 1,600 characters (about 400 tokens) a Unit. Every block after a sheet's first repeats the header row, so a Passage of about 500 tokens takes in a block or two and knows its columns. Passages never run from one sheet into the next. At most 20,000 rows (500,000 cells) of a workbook or CSV are read; the grid says so when it stops.
  - Plain text: up to 50 lines and about 4,000 characters a Unit.
  - Word or Markdown: a section is split into parts past 6,000 characters.
  - Transcript: at most 40 cues and about 1,600 characters a Unit.
- **Size limits for Office files** (#77). A Word, PowerPoint or Excel file over 500 MB is refused before it is read, and reading stops once a package's parts have inflated past 1 GB together; both fail the Document as "too-large". Per part: 64 MB read whole, 256 MB for a streamed sheet. A Word import takes inline pictures of up to 10 MB each, 64 MB a file.
- **A cell's number beside how it shows** (#435). A calculation should use what Excel computes with (0.04213), not the 0.042 that "4.2%" shows. A workbook's rows Unit label keeps `values`, the number of each cell whose shown text isn't that number written plainly (`{ "C12": 0.04213 }`), sparse, so no migration and no change to the text, Passages or check. Tools read it with `cellNumber` (`src/shared/units.ts`) or the core's `readCellNumber`; it is not on the bridge. A CSV keeps none.
- **Processing again.** A change to how a kind's Units are built raises `PROCESSING_VERSION`, and only the kinds whose Units changed are processed again at startup (`CURRENT_SINCE`, per kind). A PDF whose Passages come out the same keeps them and their vectors. Each version and why is in `src/core/documents/processing.ts`.
- **Other migrations:** 47 (when each web page version was fetched), 75 (kept Word packages), 89 (a web page version's pictures), 91 (a page kept as it looks).
- **The Word corpus** (#84). `npm run eval:word` imports, exports, edits and reviews each file: all 238 files pass, the two in Strict Open XML refused at import, and so do the 20 files of the tracked-changes set. CI opens each export in LibreOffice headless.
