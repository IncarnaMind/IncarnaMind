# A check runs on the User's own command-line AI, in the background

With no AI model set up in IncarnaMind, Check on a Note hands the check to the User's own AI by a link (#3373, #3587): its app opens a new chat with the request typed, the User sends it there, and the marks land when the agent reports. Every check leaves a one-use chat in that app, and each one means switching apps and pressing send (#3606).

The owner decided on 2026-11-22 that the User's own AI runs inside IncarnaMind in two steps. This record is the first: a single job the User presses runs once on their own command-line AI (Claude Code or Codex), with no window opened and no chat added in that AI's app, and its result lands where IncarnaMind's own would. The second, the assistant hosting a whole conversation on the User's agent, is ADR-0026. It works with no model set up in IncarnaMind, the default setup of every test and proof. It is for the User signed in to Claude Code or Codex with their own plan or key; a User with only a desktop chat app connected keeps the link.

## On what it rests

- Anthropic allows a product to run the unmodified Claude Code binary with each user on their own credentials, under its Commercial Terms, which are accepted before release; it forbids offering a Claude sign-in or routing requests through a plan's credentials ([legal and compliance](https://code.claude.com/docs/en/legal-and-compliance#can-customers-offer-claude-code-in-their-products)). IncarnaMind starts the `claude` the User installed, signed in as they set it up, and never shows, reads or passes a sign-in.
- OpenAI documents `codex exec` for scripted runs, reusing the CLI's saved sign-in, a ChatGPT one included ([non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)). Its app-server "has never been permitted for commercial or hosted services" (ADR-0026), so this route uses `codex exec`, never the app-server.

## Decisions

### 1. Which jobs

- **Now: Check,** of the whole Note or of its figures, pressed while no model is set up: the press that today opens the AI's app.
- **Next, once #3612 lands:** the selection toolbar's Explain, Improve writing, Shorten and Translate, each run the same way with only the Tools it needs (none for the three that rewrite; the reading Tools for Explain), its result shown where IncarnaMind's own would be. An amendment settles their details then.
- **They keep the link:** a question in the chat box (a conversation, which is ADR-0026's), a fix asked from a check's card, meeting notes, Organize and the Get started summary. Each can move later, by an amendment.
- **Never without a press.** "In the background" means without a window, never without the User asking. Nothing starts a run by itself: not checking as it lands (an outside agent that writes is told to check in its own turn, as now), not a schedule, not a Task. Background work in ADR-0022's sense still never uses the User's AI.
- **Only while no model is set up.** With one, Check runs IncarnaMind's own check, as now.

### 2. Which agent

- **One can run in the background** when its pairing was set up for Claude Code (`claude-code`), `claude` is on the login shell's PATH, as a terminal finds it (the launcher Meetings uses; looked up there without starting it, so a connection made before is asked no consent for an agent that isn't installed), it is 2.1.248 or later (restricted mode came then; its `--version`), it is signed in, and its consent is given (decision 6). Signed in is the exit code of `claude auth status` (0 signed in, 1 not), run at the press once the consent is given (decision 6), with no model call; nothing else it prints is read. A key in the login shell counts as signed in. Any other exit code, a command that can't be started, or no answer in 15 seconds says only that it didn't answer ("Claude Code didn't answer on this computer, so the check didn't start. Try again."), never that the User isn't signed in.
- **Codex is not offered yet** (decision 3): a pairing set up for the ChatGPT app and Codex keeps the link until its own run is designed and proven. ADR-0035 (2026-11-23) brings Codex in for Check, and corrects decision 3's finding on code mode.
- **Several agents:** the press uses the first that can run in the background, in the order the Ask pill lists them (connected or used last first). The card's ⌄ lists the others; one chosen there runs in the background if it can, by its link if not.
- **Only a desktop chat app connected** (Claude, ChatGPT without the `codex` command, Cursor, VS Code and the rest), or the command not found: today's link, unchanged.
- **Not signed in, or too old:** no run. The card says so in one line ("Claude Code isn't signed in on this computer. Sign in to it in a terminal, then press Check again."; "Claude Code 2.1.100 is older than IncarnaMind needs (2.1.248 or later). Update it, then press Check again."), with Ask by its link beside it. IncarnaMind never runs a sign-in or an update.
- **A host that can't start programs** (the mobile app, later) has no runner and keeps the link.

### 3. One run, and what each CLI may do

One press is one run: one process, started in a new, empty folder in the system's temporary folder and removed after it; a prompt in, the Tools' calls, one end. IncarnaMind keeps no session of it, and the CLI is told to keep none. A later step keeps one conversation per Note (#3627): the runner takes keeping a session as an option of a run, which a check doesn't use.

- **Claude Code:** `claude -p --restricted --tools "" --strict-mcp-config --mcp-config <file> --allowedTools <the check's Tools> --permission-mode dontAsk --disable-slash-commands --no-session-persistence --input-format stream-json --output-format stream-json --verbose --settings '{"disableAllHooks":true,"disableClaudeAiConnectors":true}' --system-prompt-file <a file in the run's folder>`, with `ENABLE_CLAUDEAI_MCP_SERVERS=false`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` and `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`. The prompt goes on stdin and IncarnaMind's instructions in that file, so no shell reads a line break of theirs: on Windows an npm-installed `claude.cmd` runs through cmd.exe, which ends a command at one. Claude Code documents the two switches: the first prevents "loading any CLAUDE.md memory files into context, including user, project, and auto memory files", and with the second "Claude does not create or load auto memory files". In real runs of Claude Code 2.1.330 with these flags, a marker word in the user CLAUDE.md, in a CLAUDE.md above the working folder and in that folder's auto memory reached no reply, with restricted mode alone and with the switches alone; with neither, all three did. Every built-in tool is off; restricted mode loads only managed settings and ours, and refuses to skip permissions; whatever isn't allowed is denied, never asked. In a run on Claude Code 2.1.330 with a test server in its place, the session listed only that server and its Tools, no tool of Claude Code's own, a Tool left off `--allowedTools` was denied before it reached the server, no session was saved, and the `CLAUDE.md` in its settings folder never reached the model. Meetings' check before the prompt stays: Claude Code's effective settings must show hooks off and no hook or enabled plugin in any settings source, or no prompt is sent. Claude Code's own bundled plugins load anyway; they added no tool, command or skill. Never `--safe-mode`: it drops a server given with `--mcp-config`, IncarnaMind's with it. Never `--bare`: it never reads a plan's sign-in.
- **Codex, not yet.** What runs of Codex 0.170 on a ChatGPT sign-in showed, for the record that brings it in: `codex exec --ephemeral --ignore-user-config` saves no session for a finished run, and leaves out the User's config with every server it names. IncarnaMind's server given with `-c mcp_servers.incarnamind…` gets the variables it is given by name (`env_vars`) and no others. `enabled_tools` keeps every other Tool from the model, and only `default_tools_approval_mode = "approve"` lets a call run with approvals off ("requires approval, but approval policy is never" without it). But Codex reaches every tool through code mode, so turning off `code_mode_host` leaves it unable to call IncarnaMind at all, and with code mode on, `shell_tool` and the other tool features off, it still has code mode's `exec` and `wait`, `request_user_input`, six `collaboration.*` tools that start sub-agents (still there with `multi_agent` and `collaboration_modes` off), `apply_patch`, the MCP resource tools and a clock. What code mode's `exec` and a sub-agent may reach is not known, so Codex waits for a design that holds them, and a real run of it.
- **The model.** The run leaves the User's own settings out, so Claude Code uses its default model for that sign-in, not one the User chose in those settings. A check still does; a request in a Note's conversation may name one of the models Claude Code lists (ADR-0034 decision 3).
- **Watched as it runs.** The flags are the wall; the watch is the alarm, which only notices when a flag didn't hold. IncarnaMind reads the CLI's event stream from its first message and stops the run, landing nothing, at the first sign of anything but IncarnaMind's server, and where it costs nothing it fails closed: no start message before a reply or the end, a start without its list of tools or of servers, one that lists a tool of the CLI's own or another server, or a call to any tool that isn't IncarnaMind's, one its model's servers run (`server_tool_use`) included. Such a run ends with "Claude Code stopped before it finished. Try again." A call to one of IncarnaMind's other Tools is denied by the CLI and refused by the server, and the run goes on: a real run reached for `read_request` once and then checked the Note. Claude Code names its tools and servers only once the prompt is in, before its first Tool call, so the prompt carries the Note's title and id and nothing else: the Note's text reaches the CLI only through the Tools. The CLI's flags are the first wall, the grant (decision 4) the second, and the code confirms both.
- **No OS sandbox in this step.** ADR-0026 puts a hosted agent in the OS sandbox because in its most restrictive start it still reads files on its own. Here the CLI has none of its own tools, so it reads only what IncarnaMind's Tools give it. The sandbox comes with ADR-0026, where the agent keeps its tools.
- **Environment:** the login shell's, as Meetings and Connectors get it, since the CLI may take its own key or cloud credentials from there. IncarnaMind adds only the variables above and the grant.
- **Limits.** A run stops after 15 minutes, unless the proof shows a long Note's check needs more; its output is read up to a fixed size, past which it is stopped. One run per Note at a time: while one runs, the press is Stop. The model's own limits are the plan's, which stop a run as the Monthly cap does.
- **Platforms:** wherever Meetings' runs work, macOS, Windows and Linux.

### 4. It reaches IncarnaMind's Tools only, for one Note

- **A run grant,** ADR-0026's (decision 3) in its smallest form: 256 random bits made at the press, held in memory only, never written to the database, a file of IncarnaMind's, a log or the secrets store, and gone when the run ends, however it ends, the app quits, or the pairing is disconnected, paused or loses its consent; every connection opened with it is closed then. The grant itself carries the Note: the run records no ask (#3622), so the agent's own connections gain nothing from a press, and nothing of it stands once the run ends. A press that starts a run takes back another agent's earlier ask on that Note, as asking another agent does; an ask by the link keeps #3622's rule. The shim (#351) admits it as the pairing it was made for, so every call is checked as that pairing's are (connecting agents on, Local mode off, consent in place, its Folders) and is listed in that pairing's activity.
- **Narrower than the pairing.** A grant's connection takes only the check's Tools (`check_mind_yourself`, `search`, `read_passages`, `cite`, `run_analysis`, `report_check`), for the Note pressed only: any other Tool or Note is refused by the server, whatever the CLI was told. The CLI is allowed those six and no others.
- **Off the command line.** The grant reaches the CLI in a settings file only the User's account can read, in the run's folder, which goes with the run.
- **The Note pressed takes its marks.** As on the link route since #3622, the grant lets the run hand back marks for that Note, a Note the User wrote included, and on a pairing that may only read, since marks change none of the Note's words. What it reads stays within the pairing's Folders: a run's `cite` opens and adds no file by its path, and a Citation the pairing was given for one elsewhere marks nothing in a run. What the Note's own marks already hold, a file cited by its path earlier included (its name, location and quote), it reads with the Note, as the link route does. Of the six Tools' inputs, `search`'s Folders, `read_passages`' Documents and Passages, `cite`'s Passages, `run_analysis`'s files and lists and `report_check`'s Citations, runs and workings are each held to the pairing's Folders, and `check_mind_yourself` and `report_check` to the Note pressed.
- **Marks are IncarnaMind's.** `report_check` confirms each Citation's quote at its Location, or the run, or the working, as for any agent; a supported or contradicted result with none is marked Not checked. Nothing the CLI says about its own checking changes a mark.

### 5. Where it shows, and how it stops

- **The asked line on the Note** (#3587), which the card and the check badge read, starts at working, "Checking this note in Claude Code.", with Stop beside it. It doesn't go quiet, since IncarnaMind knows the process runs, and it ends when `report_check` lands the marks, as now.
- **Stop** ends the process and every process it started, at once, and lands nothing. So do quitting, disconnecting the agent, turning connecting agents off, Local mode, taking the consent back, and the Note or its Folder leaving the agent's reach.
- **When it fails,** the line says why in one sentence, with Check again, and Ask by its link in the ⌄: not signed in or too old (decision 2); the plan's or key's limit, the account's billing or a lost sign-in, only where Claude Code's stream names that category for the request that failed last, on a retried request's `api_retry` or a failed one's assistant message, never guessed from its text ("Claude Code stopped: your Claude plan or API key has reached its limit. Try again later."); out of time ("Claude Code took longer than 15 minutes, so the check stopped. Try again."); no marks handed back ("Claude Code finished without marking this note. Try again, or ask it in Claude Code."); a hook or plugin an organization set, which a run can't start beside (decision 3: "Claude Code can't run here beside a hook or plugin your organization set. Ask it in Claude Code instead."); the Note out of its reach since ("Claude Code can no longer read this note, so the check stopped."); Local mode turned on ("Claude Code stopped: “Keep everything on this computer” is on."); the consent taken back in Settings › Privacy ("Claude Code stopped: running it in the background was turned off in Settings › Privacy."); anything else ("Claude Code stopped before it finished. Try again."). A report on sentences the User changed since is refused as on the link route and the agent takes them again, so the User may go on writing. The cause goes to the log, never the CLI's own output on screen.
- **Nothing opens and nothing is copied:** no link, no window, no clipboard.

### 6. Consent (ADR-0022)

- **A data flow, "hosted-agents",** the one ADR-0026 names, with one service per pairing, listed on the Privacy page and revocable there. What it sends is what the pairing's "agents" flow already lets the agent read: the Note's sentences, and the Passages and Note text its Tools give. What is new is that IncarnaMind starts the program, on the User's plan or key.
- **Agreed once, where the agent is connected.** Connecting Claude Code, in first-run setup or in Settings, says one more sentence, in the owner's words of 2026-11-22: "With no AI model set up here, pressing Check starts your Claude Code in the background to check the note. Nothing opens and no chat is added. It reads only what IncarnaMind gives it, and uses your own Claude plan or API key." Connecting is the consent, recorded beside the pairing's own.
- **A connection made before** asks once, in the consent dialog every flow uses, at its first press that would run in the background, before anything of the agent starts, its `--version` included. No keeps the link for that agent; Settings › Privacy can allow it later.
- **What is remembered:** that decision, on this device, with its date; consent never syncs. Of the run, only the marks, the AI use record and the pairing's activity, as for any check by the User's AI.
- **Taken back** in Settings › Privacy, or by disconnecting: a running run stops at once, and Check goes by the link again, with no dialog, until the User allows it in Settings › Privacy (or connects the agent again). Local mode pauses every pairing, so nothing runs.

### 7. What we never do

- Show, run, read or pass a vendor's sign-in, key or token, or read an agent's settings or session files: the status commands' exit codes, the settings check before the prompt (hooks and plugins only, decision 3), and in a Note's conversation the models Claude Code lists (ADR-0034 decision 3) are all that is read. The rest of that last answer, the account it names among it, is left unread.
- Bundle or download a CLI. IncarnaMind starts what the User installed.
- Detect, suggest or set up a plan route.
- Start a run the User didn't press.
- Keep the CLI's chat: no session saved by the CLI, no transcript kept by IncarnaMind.

## How it relates to ADR-0026

This is the smaller step before it. It shares the User's own agent on their own sign-in, IncarnaMind's MCP server through the shim, the run grant (here bound to one Note and the check's Tools), the "hosted-agents" flow, the agent list's per-agent facts (command, lowest version), and Citations only as IncarnaMind confirms them. It leaves to ADR-0026: ACP, a whole conversation streamed into the assistant, the agent's own tools with the OS sandbox and the approval card, Note edits applied with Undo, and every other agent on its list.

It amends ADR-0026's decision 6, "Background work never uses a hosted agent… checks…": a check the User presses runs on their own CLI while no model is set up; work without a press still never does. ADR-0026's line on Claude Code (a third party's product built on the Agent SDK may not offer a claude.ai sign-in) is about running the SDK inside IncarnaMind; this starts the User's own `claude`, which the page above allows.

## Considered options

- **The link only.** Rejected: one chat per check, and an app switch and a send each time (#3606).
- **Codex's app-server,** as Meetings uses it. Rejected: not permitted for commercial services.
- **The Agent SDK inside IncarnaMind.** Rejected: such a product may not offer a claude.ai sign-in, and the agent's loop would be IncarnaMind's code.
- **The pairing's own token in the run's settings.** Rejected: it outlives the run, reaches every Tool and Note the pairing does, and would be one more copy of it on disk.
- **`claude --bare`.** Rejected: it never reads a plan's sign-in, and Users on a plan come first.
- **The OS sandbox now.** Not now: with every tool of its own off, the CLI has nothing for it to hold back, and its probe, proxy and helper process are ADR-0026's build.
- **Checks as they land, on the User's AI.** Rejected: a run the User didn't press would spend their plan without asking.

## Consequences

- Meetings' Claude Code path moves to `src/main/claudeCode.ts`, one turn of the User's Claude Code that both Meetings' tool-free requests and the check run start; Meetings' Codex path stays as it is. The check's runner (`src/main/ownAi.ts`) holds the lowest version and the watch, and the core takes it as an adapter, as it does for Meetings: `src/core` still imports no Electron.
- `src/core/agents/` gains run grants beside pairings, each holding its Note and the check's Tools (`./askedChecks`) and the connections opened with it, and the run itself (`./ownRun`).
- `dataFlowIds` gains "hosted-agents"; the Privacy page, `docs/privacy.md` and `docs/where-your-data-goes.md` name it.
- **Before it is offered,** Claude Code passes a real run with no model set up in IncarnaMind. Codex follows in a record of its own, once a design holds what decision 3 found its code mode still reaches.
