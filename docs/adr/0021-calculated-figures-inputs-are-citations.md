# Calculated figures: inputs are Citations, a program does the arithmetic, and the check never says "correct"

When an Answer says "revenue grew 25%", the 25% used to be the model's own arithmetic. Neither the User nor IncarnaMind could see how it was worked out, and a wrong input or a slip in the sum looked exactly like a right one. Models are least reliable exactly there: percentages, changes in percentage points, and scales such as 万, 亿, millions and billions.

So a number an Answer works out from numbers in Passages is a **calculated figure** (CONTEXT.md), and the model never writes it itself (#438). It calls a Tool, `calculate`, which comes from the Documents, as `search_documents` and `cite` do, and is reserved like them. For each figure it gives a marker, its inputs and a formula. IncarnaMind gives back the result, and the model writes the marker (`[=1]`) where the number goes, beside its Citation markers (`[^1]`).

## The model of a calculated figure

- **An input is a Citation plus a number read from its exact characters.** The model names a Citation it recorded with `cite`, or a Passage, Location and quote, and the number as it is written in the quote ("1.2亿") or by its position. It never types a value. IncarnaMind checks the quote as the Citation check does, and reads the number with the one number reader (`src/shared/figures.ts`). A new Citation or calculation input's quote must identify one place in its cited Units, in every Document kind: repeated words or numbers need enough surrounding words to distinguish their place (#1979). This replaces the earlier first-match placement and number-only relocation rules. Tool inputs keep the supplied Location; structured output retains loose Passage naming and can place a quote elsewhere in its Passage only when its place is unique. A stored Citation is rechecked in its stored Units, never moved to another matching occurrence. Literal unit-line reads and ordinary quote-presence checks retain their contracts.
- **What the text doesn't settle is never guessed.** The model is told in one line, and it fixes the input. This covers a number the quote doesn't have or has twice, and a separator, sign, range or kind of points the reader can read two ways (the model picks one of the readings it is offered). It covers a "¥" that could be yuan or yen, which the model must settle with a quote that names the currency: a Chinese Document that names 日元 leaves it open rather than reading it as the yen, and a Japanese one that names yuan likewise. And it covers a number with no scale of its own on a page that states one ("单位：万元"), when the result depends on it: the model must quote that heading line as `unitQuote`, which is a Citation too. A sheet's unit cell in the number's own row ("31000 | 万元") states it as a heading does, so the row is that line (#1798). A statement that writes its currency on its first amount ("Sale price £385,000.00" over bare deductions) states it for the bare numbers below it in its own Passage, and the model quotes that line as it does a heading; but only where every amount is a full money amount of two decimals in one statement block, in one table column, and the Document states no scale anywhere: no scale line the reader knows ("in thousands", "单位：万元"), no currency written next to a scale token ("£'000", "€ Mio.") in a title or a running header read before it is stripped, and no page read before this build kept that marker, since a scaled statement almost never writes two decimals of the scaled unit. A Passage that names two currencies gives neither, a statement in a scale gives nothing, and one that isn't two decimals is left as before (#1001). The reader knows a scale written with zeros ("'000", "000s", "(000 omitted)"), joined to a currency ("TEUR", "k€", "$K", "$MM", "USD MM") or as a Chinese column's unit ("金额（万）", "單位：新台幣仟元", "港幣百萬"). A scale stated only in a Word section's header or footer, or a PDF's running header, is kept with its Units though no Passage holds it; since no unitQuote can quote it, a number under it that the result depends on is refused. So is one under a form that reads more than one way ("in MM": millions, millimetres or months; "$T"): it is never guessed (#2365). When the scale cancels out, as in a growth rate, it isn't asked for.
- **In a workbook, an input uses the number the cell stores** (#435), not the one it shows rounded.
- **The arithmetic is done by a program**, our own evaluator of a small part of Excel's formula language (`src/shared/formula.ts`). Its units travel with the values, so a combination that can't be right is refused, not computed. A difference of two percents is percentage points, never a percent.
- **Numeric signs can be counted without changing units** (#2002). The bounded function set is SUM, AVERAGE, MIN, MAX, ABS, SIGN, ROUND, RRI and SQRT. SIGN takes one numeric value and returns the dimensionless number -1, 0 or 1; it refuses yes/no values, missing inputs and arithmetic errors. Counting positive annual changes with `SUM(MAX(SIGN(later - earlier), 0), …)` keeps every checked input, including the base period. SIGN is an additive function under formula engine version 1; existing formulas and unit rules keep their meaning.
- **A formula never changes a scale itself.** Inputs are read in base units with their scale applied, so a power of ten that moves an amount into another scale ("rev / 10000" for 万 to 亿, "rev / 1000" for millions to billions) would make the figure that many times too small; the Tool refuses it and says to give the figure's `scale` instead (#577). A power of ten that makes a rate per so many of something stands: it scales a quotient (beds / people × 10,000), or a quantity that then divides (rev / (users / 10,000)).
- **A figure keeps everything a check needs to run it again**: its inputs with their Citations, the characters and offset of each number, the reading chosen, the cell, the unit line, the formula, the result, its shown text and how it was shown, and the evaluator's version (`FORMULA_VERSION`), so a later version runs the same rules.
- **The check never says "correct".** Every input is found and still reads the same, and the arithmetic gives the same result: that is all it can show. Whether these were the right numbers to use is shown for the User to judge, from each input's label, period and quote. The words are "Calculated" (计算得出) and "Inputs found · recalculated", never "verified".

- **Only models measured to use it are offered it.** The Tool, its steer and structured output's `calculations` are on for a model whose catalog facts say `calculates` (`src/core/providers/catalog/overrides.ts`): Anthropic's and OpenAI's models (the ChatGPT plan serves OpenAI's), from the by-hand checks of #438. Every other model, Ollama's local and cloud ones included, answers as before until the evaluation (#441) measures it. Amended 2026-10-25 (#1796): a reply that says a calculation ran when no `calculate` call worked a figure out is asked about once in the Tool loop, and keeps a line under it that its worked-out figures are unchecked if it still says so, which goes with it into a Note; a model that answers without Tools, which can't be asked again, is told in its instructions that it has no calculation Tool. A `calculate` call backs that claim only where the reply shows its figure, since a call whose figure the final reply leaves out is dropped from the Answer's record before the User reads it.

## How it is written and kept

- **Markers.** A marker with no figure is left out, and the Answer's end says how many figures couldn't be calculated. A number the model wrote right before its own marker is left out when it reads as that figure, so the text shows it once. One that differs ("26%" where IncarnaMind calculated 25.0%) stays, and the figure keeps what the Answer wrote there, for its card to show (#439). A scale or currency written right after the marker is left out, as the shown text has its own; when it isn't the figure's ("亿元" after a figure in 万元), the figure keeps it as what the Answer wrote (#577). Markers in code stay as they are.
- **Conversations (ADR-0017)** keep a `figures` list on each Answer beside its Citations (migration 67). Reopening a conversation, Add to note, search and Question context all read the same figures, and the last two read each as its shown text. The old versions of Documents that a figure's inputs quote are kept as a Citation's are.
- **In a Note**, content schema 31 keeps each calculated figure as an inline node (#439). The node owns its input Citations, exact number characters and offsets, chosen readings, raw workbook values, unit-line Citations, formula, value, display options and evaluator version. Its `=n` marker follows its place in the Note. The Figure schedule shows these and the Note's other figures as the numerical part of the same Check, with results inside the sentence's check.
- **An Analysis figure** refers to a run owned by the Note's Yjs document, kept once with its code, input references, runtime provenance and only the result values used by its remaining figures. The Note never keeps the run's whole output. Removing its last figure removes the run in the same transaction; Undo, copying and Checkpoint restore carry the figures' dependency closure. A retained generation result is never described as recalculated.
- **Source retention** uses the existing `retained_versions` table's `note-figure` owner kind as a derived projection of that Note-owned evidence, rebuilt by the same function on writes, open and Checkpoint restore; those rows keep quoted versions alive and never decide a figure's result.
- **Older builds' saved pages** need a compatibility alias under the existing `checkpoint` retention kind, with a `note-figure:`-prefixed owner. The same projection function writes and releases both kinds; History and its list, count, compare and restore APIs read real Checkpoints only. The alias keeps pages that older collectors would otherwise delete, including when the original PDF is gone, and can be removed once no supported build predates content schema 31.
- **Small local models in structured output** can't call Tools. They give their figures in their JSON, which is read in the same way. One request to fix the figures in error follows, as the second chance at quotes does (ADR-0007). A figure still in error is dropped, and its marker left out.
- **The Answer's steps** say "Calculated 2 figures" (计算了 2 个数字), with no Tool-call card, as for `cite`.

## Considered options

- **Let the model write the number and check it afterwards.** Rejected. A check after the fact can only say whether a number appears in a quote, not how it was worked out. It would also flag every figure that was worked out correctly.
- **A general code interpreter for every figure.** Rejected for a figure in a sentence. A formula over cited inputs works with every model, small local ones included, runs at once and offline, and a User reads it without reading code. Analysis over whole sheets is a separate capability.
- **A formula library** (`mathjs`, `expr-eval`). Rejected in #437: both have had code-execution advisories, and neither carries units or rounds as Excel does.
- **Guessing a scale from the table it is likely in.** Rejected. A wrong scale is off by four orders of magnitude and looks plausible, so the heading has to be quoted.

## Consequences

- For the models offered it, the steer adds about 130 tokens to every Answer's instructions in the Tool loop, and a paragraph to structured output's. The Tool's description carries an example, since some models (gpt-oss on Ollama) are shown a Tool's top-level parameters only. One Answer may call it three times, as it may search five times, so a model that can't get a figure right still answers.
- The figure's card, its margin marks, Recalculate and the marks for figures worked out without the Tool build on this model (#439, #440, #442). The evaluation measures how many worked-out figures go through the Tool, per model and language (#441).
