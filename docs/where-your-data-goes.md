# Where your data goes

**English** · [简体中文](where-your-data-goes.zh-CN.md)

IncarnaMind reads, searches and indexes your files here. It has no account or server for them. Data leaves only to a service you choose, where a line says what goes; a model on this computer sends nothing. Settings → Privacy lists every flow; [privacy.md](privacy.md) has every field.

A Connector Tool that can change something asks first, saying what kinds of text the Answer read, unless you set it to `Always allow` (after the Answer reads a web page, someone else's file, or someone else's text in the Note, it asks anyway); a read-only Tool runs without asking.

`Skill scripts run here and can send what they read. Each asks before it runs, unless you set it to Always allow.` On Windows, and on Linux without bubblewrap, nothing confines a script, so it can reach the network.

Also on the chat flow: a Note the assistant reads, what a command found, and the Note text `Make this a Skill` drafts from; when the model cannot use Tools, the Question rewritten and translated as search queries to the quick-tasks model, which can be another provider. The quick-tasks model also receives an Answer with its Passages, to find the quotes behind its Citations, and, after an assistant turn that could change your notes or run a command, the reply with the Question it answers and the record of what the Answer's Tools did, to check what the reply says was changed. The record holds each Tool's name and outcome; the names of the Notes and items it touched, and of the Note you were in; the part of a Note it named, with, for an edit, how many paragraphs and headings it edited, added, took out whole or left as they were, and where the part sits in the Note by paragraph number; how many of your sentences an edit took out whole, took words out of, rewrote, wrote new or kept, without the sentences themselves; and counts. For a command it holds the command's name and the setting, format or style the call named, the names of what it acted on, a saved file's name, a setting's name with its old and new value (a folder as its last part alone), the Folder and Tag names it proposed and the names of Tags it merged, and what else you asked as the command passed it on. A command that failed shows only that it failed. The record holds no internal id and no file path. [privacy.md](privacy.md) has the limits.

## Nothing of yours goes without a choice

With `Keep everything on this computer` on, every cloud flow above stops or uses a local model, and usage data is turned off and stays off. Still happening: update checks to GitHub at startup in the installed app, unless off; model downloads from huggingface.co and its mirrors, IncarnaMind's copies once set up, and IncarnaMind's own Python from github.com (on macOS and Linux), with the request to huggingface.co and hf-mirror.com that picks the model source, plus Ollama pulls (nothing of yours); crash reports, if you turned them on (stripped of your content first; they hold the error, when and where it happened, the app version, your system and its version, your computer's chip type and model family, its processor count and memory size, and the versions of Electron, Chrome and Node); a page you name waits for you to let it go; and a local Connector keeps working and can reach the network itself.

Usage data goes only from a build with an analytics project and only if you choose Send (a test build sends until you turn it off); while it is on, one event a week also says roughly what that week's model calls cost, as a range, the kind of route that paid, the kind of provider most of that spend went to, and how many Answers and checks there were; [privacy.md](privacy.md) lists every field. Crash reports only if you turn them on; sign-ins to ChatGPT, a Claude account or GitHub go only to that service.

IncarnaMind registers links of its own on this computer (incarnamind://): one names a Note, file or Canvas by its id only, and opening it shows that item if it is here. It sends, writes and asks nothing, and uninstalling takes the registration out.

An export you send yourself carries quotes from your Documents with their names; a web page to share also holds the passage around each quote and a picture of part of its page.

A deck you edit by hand, on its slides, sends nothing. A deck of your own is written itself, and IncarnaMind first keeps the file as it stood in its data folder (for each deck, the file as it first was and up to 9 more), so ⋯ › Put back as it was writes back the file as it stood before the latest sitting, and Put back as it was before IncarnaMind first changed it writes back the file as it first was. A change that can't be written waits in IncarnaMind's memory only, until you save it as a copy beside the file or try again: it lasts while IncarnaMind runs, so quitting asks first, and a crash or a power cut loses it. A change an AI proposes is never written into your file.

An AI agent you let write can have IncarnaMind read picture files on this computer for a Note or a Canvas it writes: only the files it names in that call, each where it is, never through a link. IncarnaMind keeps them in that Note or Canvas and sends them nowhere. It can also hand over a deck, workbook, Word file or PDF it made: IncarnaMind reads that one file from the path the agent names, the same way, keeps a copy of each version in its data folder, and checks it as "Check someone else's file" does, when you press Check on its note or, with "Check what the assistant and your own AI write" on in Settings → AI, as it lands: on the AI model you chose for checks and only when you allowed checks to go to its service.

Your keys stay here and go only to their own service, except an AI agent's pairing key: a plain-text copy is in the agent's settings, setup command or install bundle, and any process under your account can read it, so keep it private. There is no sync: nothing is uploaded to an IncarnaMind account; there isn't one.
